## 计划偏差与裁决

1. 计划假定 `stk_limit` 含 `pre_close`，生产响应证实不含。使用同源 `daily` 直接字段，
   provider 按交易日缓存，未增加每日 API 调用。
2. 计划要求指数 volume 保持 int64 并在遇小数时报错。全历史实测 5,270 行中有
   186 行含小数；继续 int64 无法完成无损接入，因此 schema 升为 Float64，并兼容旧整数值。
3. 计划示例一次读取 `namechange`，生产首批正好 10,000 行，实际还有第二页。
   已增加分页，避免静默截断。
4. `tushare_daily.name` 恒为 null，不能继续沿用旧 flags 逻辑；已接入 Task 7 的名称区间表。
