## 为什么要补这一段

计划 C Task 10 把 `build_daily_flags` 的底层从 `paid_daily` 切到 `tushare_daily`，
这是 `daily_flags` 的**第三次**改动（前两次是 ST 真值、因子直取）。
原执行记录（`artifacts/Tushare剩余计划执行记录_2026-09-14.md`）只报了终态行数，
没有出新旧逐键对账。没有对账就无法把候选池的变化归因到这次换源上——
而三段式验收（spec §10）的整个意义就在于逐段隔离、差异可归因。

## 根因：`namechange` 的区间在 2006-10-08 断掉且无后继

`is_st` 由名称区间派生。`namechange` 只记录**变更事件**，不是逐日名称快照。
实测受影响标的的区间形态：

`000006.SZ`（缺 896 个交易日，即 2023-01-03 ~ 2026-09-11 全区间）：

| name | start_date | end_date |
|---|---|---|
| 深振业A | 1992-04-27 | 2006-01-11 |
| G深振业 | 2006-01-12 | **2006-10-08** |

最后一个区间 `end_date` 非 null 且**没有后继记录**，于是 2006-10-09 之后
全部没有区间覆盖 → `name` 为 null → `is_st` 为 null。

`000023.SZ`（缺 78 个交易日，2023-01-03 ~ 2023-04-28）是**区间中段的空洞**：

| name | start_date | end_date |
|---|---|---|
| G深天地 | 2006-03-17 | 2006-10-08 |
| ST深天 | 2023-05-05 | 2024-05-05 |
| \*ST深天 | 2024-05-06 | null |

两种空洞形态都源自同一件事：**2006 年股改 G 股摘牌那一轮改名之后，
名称恢复原状的那次「变更」没有进 `namechange`。**

114 只受影响标的里，完全没有任何 `namechange` 记录的只有 1 只。

## 链路：null 如何变成消失的首板

```
name = null → is_st = null → limit_pct = null → limit_up = null
  → (close >= limit_up) = null → .fill_null(False)（flags.py:257）
  → is_limit_up = False → is_first_board = False
```

这正是 `deferred-corrections.md` D-6 描述的那条静默失效链，只是幅度从
「全市场」缩到了 **2.05%**。

**D-6 的闸门确实起作用了**——`_assert_name_coverage`（`flags.py:90`）
在 null 占比超过 10% 时显式报错，`build_daily_flags` 的逐年循环里有调用点
（`flags.py:160`）。2.05% 没有触发它，所以这次退化是**静默**的。
闸门按设计工作，但这个失效模式落在它的阈值之下。

## 候选池未归零（D-6 的核心风险已解除）

生产实测 2026-09-01 ~ 09-11：`daily_flags` 46,865 行 / 9 个交易日，
`is_limit_up` 为真 577、`is_first_board` 为真 457，候选池 **422 组**，非空。
全区间首板 49,658 个。**D-6 最坏情况（候选池永远为空且不报错）没有发生。**

## 建议的修法（未实施，需拍板）

按「只许直取或纯派生」的硬规矩，可选的只有直取：

**方案一（推荐）：历史名称仍取自 `paid_daily`，增量名称取自 `namechange`。**
`paid_daily` 有逐日 `name`、本区间 100% 覆盖、是直取字段，且历史是静态的
——不再依赖手动转存的时效性。两个直取源各管一段，不含任何推断。
代价：`daily_flags` 的历史重算仍需要 `paid_daily` 在库。

**方案二：用 `stock_basic.name` 补齐尾部空洞。**
对「最后一个区间 `end_date` 非 null 且无后继」的标的，用当前名称向后补。
**这一条含推断**——「此后没有改过名」是假设不是事实，与规矩冲突。不推荐。

**方案三：接受现状，把 2.05% 记为已知缺口。**
代价是 867 个首板信号永久缺失，且缺失集中在老上市标的上，有系统性偏差。

按用户 2026-09-13 定的原则——尊重数据等客观事实、按数据正确性重新计算——
**方案三不符合该原则**，方案一是唯一既修对又不违规矩的路径。
