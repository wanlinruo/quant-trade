# 付费日线数据高置信度修补方案

日期：2026-09-12
状态：方案已执行第一、二批；结果见 `付费日线数据高置信度修补执行报告_20260912.xlsx`

执行结果：已发布两个可撤回旁路批次，共接纳 1,546 个逐字段修补值；原始
`paid_daily` 的 37 个年度分区 SHA256 发布前后完全一致。冲突或双源覆盖不足的
记录没有修补。

## 1. 目标与硬约束

目标是在不污染源数据的前提下，提高付费日线数据的完整性、有效性和准确性。

硬约束：

1. 只接纳外部接口直接返回的字段值。
2. 禁止用公式反推、复权换算、插值、前后填充、均值、模型或人工猜测生成修补值。
3. 证券代码转换、日期格式转换、字段改名及有明确单位定义的精确单位换算属于格式标准化；标准化前的原始响应必须永久保存。
4. 对已知异常或缺失值，付费源本身不计入交叉验证票数；至少需要两个相互独立的外部上游一致。
5. 无法达到准入标准的数据保持原值或 null，并标记为未解决，不以完整率为目标强行补齐。
6. `paid_daily` 原始表永久只读。修补结果进入独立旁路表和独立查询视图，不覆盖原始分区。

## 2. “独立数据源”的定义

`a-stock-data` 是接口适配工具，不作为一个数据源计票。按它实际调用的上游分别计算，例如 BaoStock、新浪、百度、腾讯、东方财富、交易所官方接口。

以下情况只能算一票：

- 同一上游的不同包装库、镜像或不同 API 路径；
- mootdx 与另一个仍然读取同一份通达信文件/服务的数据接口；
- 同一网站的网页接口和移动端接口；
- 一个来源转载另一个来源的数据，且无法证明独立生成链路。

每个来源登记 `source_family`。只有不同 `source_family` 才能参与双源一致判定。来源独立性不清楚时按同源处理。

## 3. 修补准入规则

### 3.1 通用规则

每个候选修补单元以 `(symbol, dt, field)` 为主键，必须同时满足：

1. 两个外部独立来源都直接返回该证券、该交易日、该字段；
2. 代码映射、交易日、币种、单位及字段语义一致；
3. 两源值按下述字段规则一致；
4. 至少一个来源属于稳定历史接口，不能由两个仅面向当前行情的接口补历史值；
5. 原始 HTTP 响应或客户端原始返回已归档并计算 SHA256；
6. 修补后通过行级约束、跨日约束和全库回归检查；
7. 生成修补前审阅清单后才发布到修补层。

两个来源冲突时引入第三个独立来源。只有至少两路直接值一致，且不存在代码映射、口径或公司行动疑点时才可接纳。简单多数不能覆盖明确的语义冲突。

### 3.2 字段一致规则

| 字段 | 一致条件 | 明确禁止 |
|---|---|---|
| open/high/low/close/pre_close | 按来源共同声明的价格精度完全一致 | 用涨跌幅或前后价格反推 |
| volume | 先确认来源单位，精确换算后完全一致；落库值取指定主来源的直接值 | 用 amount/price 反推；不明单位时换算 |
| amount | 落库值取指定主来源的直接值；第二来源须落在其公开精度产生的舍入区间内 | 用 price×volume 计算；使用任意误差百分比放宽 |
| change/pct_change | 两源都必须直接提供且口径一致 | 用 close-pre_close 或比例公式计算 |
| factor | 两源均直接提供相同复权方向、累计定义和相同锚点的因子，值完全一致 | 用公司行动计算；把新浪前/后复权因子缩放到付费源基准 |
| turnover/volume_ratio | 两源直接字段、分母定义一致 | 用成交量和股本计算 |
| total/circulating/free shares | 两源直接值、股本类别及生效日一致 | 从市值和价格反推 |
| market cap | 两源直接值、币种和时点一致 | 用价格和股本计算 |
| PE/PB/PS/股息率 | 两源直接值，静态/TTM、亏损处理、报告期和除权口径一致 | 从财务报表或市值计算 |

## 4. 数据分层与审计结构

建议增加四层，原始 `paid_daily` 不变：

1. `repair_raw/`：按来源和抓取批次保存原始响应、请求参数、抓取时间、接口版本和 SHA256。
2. `repair_observations`：把外部原始响应标准化为逐字段观察值，同时保留原始代码、原始文本、原始单位和来源族。
3. `repair_decisions`：保存每个候选单元的原值、候选值、两路证据、规则版本、判定状态和拒绝原因。
4. `paid_daily_curated`：只读取状态为 `ACCEPTED` 的修补单元，生成独立的可信查询层；每个修补值可回查 `repair_id`。

判定状态固定为：

- `ACCEPTED`：满足全部准入条件；
- `CONFLICT`：来源间数值或口径冲突；
- `UNAVAILABLE`：免费源没有该历史字段；
- `SEMANTIC_MISMATCH`：字段名称相似但定义或锚点不同；
- `LEGITIMATE_NULL`：上市首日、亏损估值、停牌或其他业务原因导致的合理空值；
- `PENDING`：证据尚不足。

查询结果需能同时看到修补后的值和修补标志；质量报告分别统计原始层和修补层，避免修补掩盖源数据问题。

## 5. 现有异常的处理顺序

### 第一批：高成功概率、低语义风险

1. 21 条 OHLC 关系异常：先处理 19 条 1991—1994 年沪深记录；对每个字段分别获取 BaoStock及另一独立历史源的直接日线值。2 条 `920489.BJ` 历史异常单列，不因沪深结果推及北交所。
2. 232 条 amount 缺失：先做小样本历史覆盖探针。只有两个独立来源均直接返回成交额且舍入口径相容时补入。

### 第二批：需要判断是否为合理空值

1. 241 条 pre_close/change/pct_change 缺失：先核对是否为证券首个交易记录或上市首日。合理首日空值标记为 `LEGITIMATE_NULL`。非首日也只接纳外部直接字段，不进行算术补齐。
2. 股本、市值、换手率及估值字段：先建立“该字段当日是否应存在”的判定，不把亏损导致的 PE 空值、未分红导致的股息率空值等当作错误。仅对确认异常的单元做双源采集。

### 第三批：低成功概率或高口径风险

1. 1,448 条 `600018.SH` factor 空值：新浪因子可用于验证公司行动日期，但若锚点与付费源不同，不允许缩放后入库。找不到两路相同口径的直接累计因子时保持 null。
2. 1,800 条复权自洽规则命中：该规则本身只是异常线索。先区分“昨收口径差异”和“因子错误”，只有相同口径的直接因子双源一致后才能修补。
3. 北交所/新三板历史字段：当前免费源覆盖不足，统一保留为 `UNAVAILABLE` 或 `PENDING`，后续等待新的历史直取源。

## 6. 外部来源使用策略

第一轮候选来源：

| 来源 | 使用范围 | 限制 |
|---|---|---|
| BaoStock | 沪深历史 OHLC、成交量、成交额，2016 年后部分估值和换手率 | 不支持北交所；估值字段有限 |
| 百度/新浪/东方财富历史行情 | 作为沪深价格和成交额的第二或第三票 | 必须先实测历史深度、代码路由和接口稳定性 |
| 新浪复权因子 | 验证沪深公司行动日期和因子变化 | 不同锚点不允许转换后修补；不支持北交所因子 |
| QMT | 现有覆盖期内价格等直接字段的验证 | 自算因子和公司行动推导值不能作为修补值 |
| mootdx | 历史日线候选证据 | 与现有通达信链路同源时只算一票 |
| 腾讯、北交所官方当前行情 | 当日或近期核验 | 不用于历史回补 |

所有接口先进行“能力探针”，验证最早日期、退市证券、北交所代码、停牌记录、字段单位和错误证券防护。探针失败的接口不进入正式采集。

## 7. 执行阶段与闸门

### 阶段 A：只读探针

- 对每类异常抽取少量代表记录；
- 验证候选来源真实历史覆盖、字段语义和来源独立性；
- 保存原始响应；
- 输出“可用来源矩阵”，不生成修补值。

退出条件：每个准备修补的字段至少找到两个独立、可重复查询的直接来源。

### 阶段 B：全量候选采集

- 只采集异常清单中的 `(symbol, dt, field)`，不下载无关全市场数据；
- 写入 `repair_raw` 和 `repair_observations`；
- 生成 `ACCEPTED/CONFLICT/UNAVAILABLE/...` 决策草案；
- 不改任何生产查询结果。

输出：逐单元修补前审阅表，列出原值、拟采用值、两路来源值、原始响应哈希和拒绝项。

### 阶段 C：发布修补层

- 给当前 warehouse 建快照；
- 只将 `ACCEPTED` 单元写入修补旁路表；
- 原子生成 `paid_daily_curated`；
- 重跑完整性、OHLC、非负值、主键、复权自洽和字段空值报告；
- 与原始层逐字段对账，确认变化只发生在批准清单中。

### 阶段 D：观察与回滚

- 原始表始终可直接查询；
- 关闭或删除某个修补批次即可回到原始值；
- 接口后来改值时不静默刷新，生成新的版本和差异报告后重新判定。

## 8. 发布验收标准

一个修补批次必须同时满足：

1. 原始 `paid_daily` 所有分区 SHA256 不变；
2. 修补记录数与审阅表中 `ACCEPTED` 数完全一致；
3. 每个修补单元有两路独立原始证据和可验证 SHA256；
4. 没有任何值来自禁用算法或计算字段；
5. 除批准清单外，修补前后逐字段零差异；
6. 主键无重复，OHLC 等硬约束不新增异常；
7. 冲突、无来源和合理空值均保留，不因追求覆盖率而写值；
8. 修补层可按批次一键撤回，撤回后查询结果与原始层一致。

## 9. 预期边界

交叉验证可以显著提高被接纳修补值的可信度，但不能证明整库绝对正确，也不能保证全部缺失都能免费补齐。按现有免费源能力，沪深少量 OHLC 和部分成交额最有希望；不同锚点的复权因子、早期北交所/新三板历史字段以及部分估值字段很可能继续保留为空或待查。这是避免数据污染所必须接受的结果。
