## 判决：直取价是对的，旧派生是错的

旧逻辑 `limit_pct = 0.05 if is_st else 板块档位`——**任何 ST 股一律 5%**。
实测反驳：

| 分组 | 股-日 | 直取档位 | 实际最高价涨幅 |
|---|---:|---|---|
| 主板 ST（直取 5%） | 16,741 | 5% | >5.2% 仅 97 天（0.58%） |
| 主板 ST（直取 10%） | 7,437 | 10% | **>5.2% 有 935 天，>9.8% 有 238 天** |
| 创业板 ST 300/301 | 7,423 | 20%（7,418 天） | >20.5% 仅 1 天 |
| 科创板 ST 688 | 1,608 | 20%（1,606 天） | >20.5% 为 0 天 |

主板 ST 中直取给 10% 的那 7,437 个股-日，有 238 天真实涨幅超过 9.8%。
若真是 5% 档，这不可能发生。创业板/科创板 ST 的真实上限是 20%，
旧逻辑按 5% 算，股价涨 5% 就被判成涨停——**假涨停**。

翻转方向与之吻合：

| 翻转 | 旧 true → 新 false | 旧 false → 新 true |
|---|---:|---:|
| `is_first_board` | 2,314 | 58 |
| `is_broken_board` | 3,296 | 142 |

首板翻转按号段：300 占 1,466、688 占 258、301 占 205，
其中 1,943 行 `is_st=true`。**旧数据系统性多报首板与炸板，集中在创业板/科创板 ST 股。**
换源是纯净的修正，不是引入噪声。

## 本轮切换引入的新缺陷

### N-1　`limit_pct` 与 `limit_up` 在同一行里自相矛盾

改动只把 `limit_up`/`limit_down` 换成直取值，`limit_pct` 仍按
"ST 一律 0.05"派生。结果：

- **68,649 行（1.50%）**的 `limit_up / adj_prev_close - 1` 与 `limit_pct` 相差超过 0.002
- 其中 45,677 行 `is_st=true`
- 号段分布：300 占 27,350、600 占 12,849、002 占 10,718、000 占 6,735、688 占 4,193
- 逐年都有：2023 年 12,667、2024 年 19,748、2025 年 15,823、2026 年 20,411

典型：`300029.SZ` 2023-01-03，`adj_prev_close=7.96`、`limit_up=9.55`（+19.97%，正确），
而 `limit_pct=0.05`。`schema.py:146` 把 `limit_pct` 注释为"实际生效的涨跌幅"——
对这 68,649 行它不是。

### N-2　`universe.py` 仍用 `limit_pct == 0.05` 反推 ST

`src/qsys/strategy/structural/universe.py:81-84`：

```python
# filter_st_paused_stock：ST 由 limit_pct == 0.05 反推得到
if "limit_pct" in yesterday.columns:
    ... pl.col("limit_pct").is_null() | (pl.col("limit_pct") > 0.05 + 1e-9)
```

两个问题：

1. 这是**反推**。`daily_flags.is_st` 现在是直取布尔真值，没有任何理由再从价格档位倒推。
2. 这是**地雷**。它现在能工作，仅仅因为 `limit_pct` 恰好仍由 `is_st` 派生。
   一旦有人把 N-1 修对——让 `limit_pct` 等于真实档位——创业板 ST 的
   `limit_pct` 会变成 0.20，`> 0.05` 判定为"非 ST"，**ST 股会静默进入候选池**。

N-1 与 N-2 必须一起改：`limit_pct` 改为真实档位，`universe.py` 改读 `is_st`。

### N-3　退市整理期股票被 `stock_st` 单日误报（4 行，影响可忽略）

2023-06-01 的 `600242.SH`／`600532.SH`／`600767.SH`／`600781.SH`：
`stock_st` 当天报 `is_st=true`、名称 `*ST中昌` 等，前后交易日均为 false；
而 `paid_daily` 逐日名称是 `退市中昌`——它们处于退市整理期，上限 10%。
`stock_st` 这一天的名称是旧的 `*ST` 名。

影响被直取价挡住了：这 4 行的 `limit_up` 新旧完全相同（0.31 / 0.69 / 0.50 / 0.69，
均为 10% 档），`is_first_board` 也没变。污染只限于 `is_st` 与 `limit_pct` 两列。

## 决定性事实：2026-07-06 主板 ST 新规

用户指出、数据证实：**2026-07-06 起主板 ST 的涨跌幅上限由 5% 改为 10%**，
与普通股相同。生效日钉得很死：

| 交易日 | 主板 ST 中 5% 档 | 10% 档 |
|---|---:|---:|
| 2026-07-01 | 149 | 0 |
| 2026-07-02 | 149 | 0 |
| 2026-07-03 | 148 | 0 |
| **2026-07-06** | **0** | **148** |
| 2026-07-07 | 0 | 149 |

一刀切，无过渡。这条新规把问题的性质改变了：

- 上文「主板 ST 直取 10% 档有 238 天真实涨幅超 9.8%」不是上游数据瑕疵，
  **是新规的正常结果**。
- 「ST 一律 5%」不是写错了一个数字，而是**规则这条路根本走不通**——
  档位随监管变化，任何写死的映射都会在下一次新规时再错一次。
- 最要紧的是：**新规之后价格再也判不出 ST**。主板 ST 和普通股同为 10%，
  反推不是「精度不够」，是没有信号。

## 修法

`limit_pct` 改为从直取涨停价**解码**：逐个试已知档位 {0.05, 0.10, 0.20, 0.30}，
取能精确还原出 `limit_up` 的那一档；解不出或解出多档一律记 null。
派生路径（没有直取价）沿用算价格时用的那个档位，本就自洽。
实现 `flags.py:_decode_tier`，先写了 4 条测试看它们红，再写实现。

`universe.py` 的 ST 过滤改读 `is_st` 直取真值，`is_st` 为 null 时排除。
