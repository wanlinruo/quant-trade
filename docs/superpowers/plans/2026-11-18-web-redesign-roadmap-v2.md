# Web 改版总路线 v2：不带旧系统的历史包袱

**日期：** 2026-11-18
**依据：**
- 维护者 11-18 决定（#662 评论“改版不带旧系统的历史包袱”）。
- 设计文档 `docs/superpowers/specs/2026-11-17-web-redesign-design.md`。

**取代：** 计划 01 中的“总路线”表；§12 中“渐进替换、新旧并存”的设计者决定。

## 1. 四项决定

1. **告警改为结构化事件。** 结构化事件（稳定键、来源、对象、级别、发生/恢复、证据、时间）是唯一来源，写入带版本的存储；通知文本由事件生成。旧的文本告警接口与账本格式在迁移完成后删除。
2. **新接口独立契约。** 新后端每个接口都有明确的响应模型并带 `schema_version`；前端类型由后端契约生成，不手写第二份；文件下载走新接口。不转储旧页面的视图对象。
3. **新页上线即删旧页。** 合入时删除被取代的旧模板、旧路由和旧接口，旧路径 308 重定向到新页。不再单独修旧代码里的问题。
4. **内部服务重写。** Web 侧为旧页面而造的视图服务，按新页面需要重写为干净的只读查询层；旧服务随旧页面删除。

**不变：** AGENTS.md 的生产安全规则不属于历史包袱，全部照旧：
- 新字段兼容 N-1；
- 先核对控制面再发布；
- 交易组件在收盘后发布；
- 不可逆操作前确认；
- 数据铁律。

## 3. 新后端结构

```
src/qsys/webapp/
  app.py            # 新应用工厂：只挂新接口与 /app 单页；旧 web 删除后成为唯一入口
  contracts/        # 每个领域的响应模型（pydantic，带 schema_version），是唯一契约来源
  queries/          # 只读查询层：直接用领域对象与存储，不含任何展示口径
  routes/           # 薄路由：参数校验 → 查询 → 契约模型；统一错误格式与 no-store
  files.py          # 受控文件下载（白名单根目录、哈希校验），取代旧页面的各类下载路由
```

- **前端类型由契约生成**：用固定版本的 `openapi-typescript`，从 FastAPI 的 OpenAPI 生成 `frontend/src/api/generated.ts`。CI 检查生成结果与仓库一致，不一致即失败。前端不再手写接口类型。
- **统一约定**：
  - 时间一律带时区的 ISO 8601；
  - 缺失值为 `null`，原因放在同级的 `missing` 字段；
  - 金额单位为元，比例取 0–1；
  - 错误体为 `{error: {code, message}}`，不回显异常文本与路径。
- **服务端缓存与读取边界**沿用已实现的单飞缓存和 §10 的规则。

## 4. 计划顺序

**第一段：需求分支 `feat/web-redesign`，不涉及生产组件。**

| 计划 | 内容 |
|---|---|
| R1 | 新后端骨架与契约机制（`webapp` 包、契约基类、OpenAPI → TS 生成与 CI 校验、统一错误格式、受控下载）；外壳状态、市场总览、AI 涨停迁到新结构，前端改用生成类型 |
| R2 | 打板看板迁到新结构（读取器迁入查询层，明确 `BoardView` 对外契约） |
| R3 | 策略、回测、研究任务：重写回测报告读取层（不再填 0），下载改走受控下载 |
| R4 | 数据组：重写数据资产、指标字典、质检查询层，直接用 `qsys.data.catalog` 领域对象 |

**第二段：独立分支，改生产组件，开发与 R 系列并行，发布等 #137 结束、收盘后进行。**

| 计划 | 内容 |
|---|---|
| 03 | 结构化告警事件：定义事件模型与受管键清单；全部生产者（实盘核心、影子核心、模拟盘、健康观察与巡检、重启演练、服务质检）改发事件；通知由事件生成；每日汇报改读事件存储；旧接口与旧账本删除。执行端心跳带 QMT 执行器状态，健康观察记入链路时间序列 |
| 04 | 告警汇总只读查询（按稳定键归并）、已知警告受管清单与基线判定、“确认已知悉”存储 |
| 05 | 停机闸受管解除入口的机器可读核对输出 |

**第三段：页面。**

| 计划 | 内容 |
|---|---|
| 06 | 今日运行、告警中心、交易组 5 页：交易查询层直接读 `live_events`、`live_strategy_runs`、实盘状态库、`health_observations` 与告警事件 |
| 07 | 运维组 3 页：采集器（节点资源、链路、进程、QMT 客户端、版本、安全核验）与服务看板查询层 |

**合入。**
- 计划 02：测试环境支持前端构建产物。
- 删除旧 `qsys.web`；业务模块搬家；旧路径重定向。
- 按组件分别发布，每一步合并与发布前都问维护者。

每份计划在前一份落地后再写。

## 5. 已有成果的处理

- 08a、08b、08c、09 的页面结构、交互、裁决、测试用例与布局冒烟全部保留，只把接口层迁到新契约。前端改用生成类型，后端改用新查询层，测试随之调整。
- 已定的口径不变，包括赚钱效应、推进位置、回测警告、质检归类、样本口径。它们迁到新查询层，作为契约的一部分。
