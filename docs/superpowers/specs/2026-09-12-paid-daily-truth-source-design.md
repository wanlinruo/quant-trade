## 一、目标与非目标

**目标**：把日线事实源从 mootdx 的 `bars_daily` 切到付费源 `paid_daily`，并在同一次
改动里把 ST 判定与复权因子从「价格反推 / 自算」换成直取真值。

**触发原因**：mootdx / 通达信免费行情的 K 线接口自 2026-09-10 起在上游整体失效
（见 §3.1）。`bars_daily`、`index_bars`、`daily_flags` 及其下游候选池全部停在
2026-09-09。这不是可以排期的优化，是生产链路已经断了。

**非目标**：

- 不改策略逻辑。本次只换数据来源与真值口径，策略行为变化单独评估（见 §10）。
- 不做停牌真值。付费源没有停牌标志，QMT 的 `suspendFlag` 单列一条。
- 不重建 `instruments` 主表（退市股问题）。单列一条。
- 不删 `bars_daily` / `valuation_snapshot`。冻结保留作本次回归的对账参照，
  验收通过后再按去重方案批次 B 处理。

## 二、硬约束

除下面一条明确的例外，全部继承既有规矩：

- **禁止编造数据。** 每一列只允许两类：直取（源的原值）、纯派生（直取列的确定性
  算术，公式写在代码与本文档里，可逐位重算）。拿不到就记 null 由质检报出来。
- **禁止启发式、阈值猜测、缺失值填充、均值、模型、人工猜测。**
- 单位换算、代码格式转换、字段改名属于格式标准化，标准化前的原始值必须可追溯。
- `paid_daily` 原始表永久只读。

### 2.1 ~~本次唯一的例外：兜底日的 ST 结转~~（2026-09-13 撤回）

> **已撤回。** 本例外原本只为兜底路径（§9）存在——付费源未到货的交易日没有
> `name` 列，故允许 ST 状态从最近一个已落库真值结转。
>
> 日线源改为 Tushare API 直连后，兜底路径不再存在，本例外随之失去适用场景，
> **予以撤回**。本设计恢复为「禁止任何填充」**无例外**。
>
> 此外 Tushare 的 `namechange` 是**区间表**（带 `start_date` / `end_date` /
> `ann_date` / `change_reason`），按区间展开成每日 ST 状态属**纯派生**，
> 比原计划从 `name` 列逐日字符串匹配更严谨——后者会把名称中恰好含 "ST"
> 的正常标的误判。

## 三、数据源实测事实

本节全部为 2026-09-12 实测，是后续设计的依据。

### 3.1 mootdx 失效

- `get_security_bars`、`get_index_bars`、`get_security_quotes` 全部返回 None；
  `get_security_count`（返回 24241）、`get_security_list` 正常。
- 配置内 38 台服务器逐台实测：14 台 TCP 可连，行情接口全空。
- 开发机宽带与腾讯云主机两个网络、三台服务器表现一致，非本机网络问题。
- 每次调用恒定等 3.8 秒返回空表。

### 3.2 两表逐字段比对（`000001.SZ` 2026-09-09）

| 字段 | `paid_daily` | `bars_daily`(QMT/mootdx) |
|---|---|---|
| open/high/low/close | 11.76 / 11.79 / 11.69 / 11.70 | 完全相同 |
| volume | 582305.98（手，带小数） | 582306（手，整数） |
| amount | 682,946,782.66 元 | 682,946,752.0 元 |
| 额外列 | `factor`、`name`、`pre_close` 等共 28 列 | 无 |

### 3.3 覆盖差异（2026-09-09）

- 付费 5,550 只，QMT 5,217 只。
- 付费多出 **343 只，全部是北交所（.BJ）**——归档脚本 `--boards main,gem,star`
  本就不采北交所。
- 付费缺少 **10 只**（5 SZ + 5 SH），即零成交停牌占位行，其 amount 为异常极小
  浮点数，本就不应进入日线主事实表。

### 3.4 `pre_close` 就是除权参考价（直取）

2026 年 3,980 个除权日（`factor` 发生变化的股-日）样本：

| 比较 | 中位数差 | 最大差 |
|---|---:|---:|
| `pre_close` vs 前一日 `close` | 0.17 | 615.32 |
| `pre_close` vs `前一日close × 前一日factor ÷ 当日factor` | **0.000154** | 15.94 |

结论：`pre_close` 是**除权后的参考价**，正是涨跌停价计算所需的基准。现有
`flags.py` 用 `corporate_actions` 事件表自算的 `adj_prev_close` 可以整段由直取替代。
最大差 15.94 的离群样本在实施时必须逐个列出并解释，不得掩盖。

### 3.5 ST 真值

- `name` 列是**当日名称**。2026-09-09 全市场 5,550 只中 201 只名称含 "ST"。
- 阶跃干净：`000010.SZ` 在 2026-04-30 由「美丽生态」变为「\*ST美丽」，
  与年报后 ST 生效日一致。

### 3.6 停牌在付费源中的表现

- `paid_daily` 中 `volume == 0` 的行数为 **0**。停牌日整行缺席。
- 2026 年 169 个交易日、5,582 只证券中，出现天数不足 169 天的有 499 只，
  其中大部分是当年新上市（如 `688801.SH` 仅 1 天）。
- **因此「缺席」同时混合了未上市、停牌、已退市三种情况，不能直接解释为停牌。**

### 3.7 现有停牌判据在新源下会静默失效

现有停牌判据是「四价等于前收 + 量为 0」。付费源零成交行数为 0，该判据在新源下
**永远不会命中**。候选池本身不受影响（候选是「昨日首板/炸板」，停牌股没有 bar
自然进不来），但这条失效必须在代码与文档中记录，不得假装仍在工作。

### 3.8 远端交付结构与时点

```
/金融数据/每日日线/<发布日期>/
├── 按交易日/<年>/<交易日>.xlsx     37 个年目录 / 8723 文件 / 3.52 GB（全量历史）
└── 按企业CSV/<代码>.<交易所>.csv    5899 文件 / 3.54 GB（同一份数据，28 列零差异）
```

- 卖家**每天重新发布一整份全量历史**，目录以发布日期命名，旧日期目录消失。
- 实测 `20260911/按交易日/2026/` 含 **169 个文件，包含 20260910 与 20260911**。
  因此漏跑可从次日目录恢复，**不是不可恢复的滚动窗口**。
- 单个交易日文件约 **1.1 MB**，每日增量只需下载这一个文件。
- 发布时点实测：`20260911` 的 `server_ctime` = **2026-09-11 17:08:59**，
  `按企业CSV` = 17:41:19。与「交易日收盘后当日更新」一致。
- 转存时点实测：该目录下全部条目的 `server_mtime` 同为
  **2026-09-12 10:17:03**，且 `owner_id`(2924352737, 卖家) ≠ `oper_id`(473560623)。
  这是一次**人工转存**的特征，本次延迟 17 小时。

### 3.9 转存无法用现有凭证自动化

百度网盘开放平台 xpan API 只覆盖自有网盘的增删改查，**没有「转存他人分享链接」
接口**；该能力属网页端私有接口，需要 BDUSS cookie 而非 access_token。
当前凭证（`~/.baidupan-cli/config.json`，2026-10-11 过期）不具备该能力。

**因此自动化的边界在转存之后。** 转存保持人工每日一次点击。分享链接与提取码存入
`config/deploy.local.toml`（已 gitignore），不进代码库、文档或日志。

### 3.10 QMT 日线通道

`scripts/win_download_daily.py` 已存在，经 Windows 节点取数，输出列：
`symbol, dt, open, high, low, close, volume(int64, 手), amount, suspendFlag`。
启动时用 `600036.SH` 2026-09-08 做 volume 单位自检，对不上直接退出不写数据。

**没有 `name`、没有 `factor`、没有 `pre_close`。**

## 四、表结构

| 表 | 内容 | 生命周期 |
|---|---|---|
| `paid_daily` | 付费源 28 列，唯一真值事实表 | 永久只读 |
| `daily_provisional` | QMT 兜底，含 `source`、`suspendFlag` | **临时**，付费到货即删对应日期 |
| `bars_daily` | mootdx/QMT 旧日线 | **冻结**，仅供本次回归对账 |
| `daily_flags` | 派生，新增 `is_st`、`st_source`、`is_provisional` | 可重建缓存 |

`daily_flags` schema 变更：

- **删**：`st_inferred_raw`、`st_inference_rejected_by_price_evidence`、
  `st_inferred_final`（反推没了，反推的审计列也不该留）
- **增**：`is_st`（真值或结转）、`st_source`（`paid` / `carried_from_<日期>`）、
  `is_provisional`（该行是否由兜底数据算出）

## 五、查询层：原地换底

去重方案 §4 的 `daily_canonical` 原本是为「付费为主 + QMT 接缝」设计的多源合并视图，
本设计采用它，但语义收紧为**分表 + 视图**，绝不混源：

- `WarehouseQuery.daily_bars()` 底层由 `bars_daily` 改读 `paid_daily`，
  投影同样 8 列 → **32 处调用零改动**
- `paid_daily()` 暴露全部 28 列，供 flags / adjust / valuation 使用
- `daily_canonical()` 视图：付费源覆盖的日期读 `paid_daily`，未覆盖的日期读
  `daily_provisional`，**每行带 `source` 列**，任一 `(symbol, dt)` 最多返回一行
- `legacy_daily_bars()` 只读冻结的 `bars_daily`，唯一用途是本次回归对账

**类型变更**：`volume` Int64 → Float64。直取不取整——取整是有损变换，付费源的
582305.98 就是 582305.98。消费点（`sim_broker` 等）随之适配。

**板块口径**：`daily_bars()` 不做板块过滤，保持「给全部」。`build_daily_flags` 与
`build_market_regime` **必须显式按板块过滤**，否则付费源多出的 343 只北交所会悄悄
进入广度因子，改变 `advance_ratio`。策略本就排除北交所，口径须对齐。

## 六、`flags.py` 重写

| | 现在 | 换源后 |
|---|---|---|
| ST | 三条价格启发式反推，近窗一致率 93.8% | `is_st` = `name` 含 "ST"，**直取** |
| 审计列 | 三个 `st_inferred_*` | 删除，换成 `is_st` + `st_source` |
| 涨跌停基准 | `corporate_actions` 算出的除权参考价 | `pre_close`，**直取** |
| `limit_pct` | 由反推 ST 决定档位 | 由真值 `is_st` + 板块决定，纯派生 |
| `limit_up/down` | round(自算参考价 × (1±pct), 2) | round(`pre_close` × (1±pct), 2)，纯派生 |

三条 ST 启发式整段删除。

**`_with_reference_price` 保留，但只服务兜底路径。** 付费路径用直取的 `pre_close`，
不再调用它；兜底日（§9）没有 `pre_close`，仍需用 `corporate_actions` 自算除权参考价。
保留下来的这条路径必须在产出行上标 `is_provisional`，不得与直取值混在一起统计。

现有 342 行预计降到 200 行上下（ST 启发式约 150 行删除，参考价计算保留）。

## 七、`adjust.py`

`factor` 由 `paid_daily` 直取。现有的自算复权**降级为校验**：两边比对，差异进报告，
不参与落库。背景：522 次因子变动中仅 7 例偏差 >1%，且 100% 落在 2005—2006 股改期间。

## 八、~~每日时序~~（2026-09-13 作废）

> **整段作废。** 原时序围绕「卖家 17:10 发布 → 人工转存 → 18:30 系统拉取」
> 设计，人工转存是其中不可自动化的一环（实测延迟 17 小时）。
> Tushare API 直连后该环节消失，新的每日时序由计划 C 定义。
>
> 原设计中仍然成立、需由计划 C 继承的两条：
>
> 1. **没拿到新数据必须显式报错退出**，不许静默当成正常。2026-09-10/11 的
>    归档超时事故根因就是上游静默返回空而系统当成正常。
> 2. **15:40 的既有归档不依赖当日日线**——竞价 tick、股本、分钟线的候选
>    均只需 T-1 的 `daily_flags`。该结论经代码核对，继续有效。
>
> `daily_archive.py` 中 mootdx 那一步仍应删除（源已死）。

## 十、三段式验收

一次交付，但分三段各出一次差异报告，否则回测一动无法归因：

| 段 | 变量 | 预期差异 |
|---|---|---|
| 1 | 只换源，ST 仍用旧启发式 | volume 小数、amount 舍入、北交所过滤、10 行停牌占位消失 |
| 2 | 加 ST 真值 | 候选池变化（现约 6% 的 ST 判定会翻） |
| 3 | 加因子直取 | 复权价变化，主要集中在 2005—2006 |

每段跑黄金回归，逐键与冻结的 `bars_daily` 对账。三段全部通过后，去重方案批次 B
的删除动作才可执行。

## 十二、风险与未决

1. ~~**转存延迟**~~。**问题消失**（API 直连）。取而代之的新风险：**Tushare 积分
   一年有效期、到期回收**（2026-09-13 购入 5000 积分）。到期未续费则日线源直接
   中断，须设到期提醒。
2. **`pre_close` 离群样本**。3,980 个除权日中最大偏差 15.94，实施时必须逐个列出。
3. **QMT 与付费源的口径差**长期存在（volume 精度、amount 舍入、北交所覆盖）。
   差异报告会持续暴露，不应试图消除。
4. **凭证到期**。百度 access_token 2026-10-11 过期，需要续期流程。
5. **单一商业数据源依赖**。已实测证实百度网盘卖家与 Tushare 同源，因此二者
   **不构成两票**，不能互为交叉验证。独立验真仍靠同花顺抽样。
6. ~~**兜底链路的静默失效**~~。**随 §9 一并作废**（不再有兜底链路）。
7. **竞价逐笔仍是唯一不可替代、且正在流失的数据**。Tushare 无等价接口；
   `auction_ticks` 截至 2026-09-13 仅 8 天。且因日线源中断导致候选池算不出来，
   **当前连采都采不了**——这使计划 A 的完成成为恢复采集的前置条件。
