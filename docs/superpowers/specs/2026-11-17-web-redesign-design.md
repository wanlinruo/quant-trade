## 0. 原型与它的地位

- 原型代码在 `.superpowers/spike-redesign/`（Vite + React 19 + TypeScript + antd 6 + ECharts 6 +
  lightweight-charts 5），本地运行 `npx vite --port 5199`，打开 `http://127.0.0.1:5199`。
- 原型是**一次性的**：全部数据是确定性伪随机的示意数据，股票代码打码，不连接任何生产接口，
  不产生任何委托。原型代码**不直接进入仓库正式代码**，实施时按本文重新实现；可以参考它的
  组件拆分和图表配置。
- 原型有三个场景，用来检验同一套页面在不同时刻是否说得通（不是正式功能）：
  - **盘中 10:42**：正常交易日盘中。
  - **晚间 20:40**：已收盘、15:30 对账完成、晚间任务跑完、日报已发。
  - **异常日 10:48**：10:31 Redis 隧道中断，10:32:35 watchdog 触发停机闸，10:36 隧道恢复但停机闸保持。
- 本文中出现的所有具体数字（涨停 68、净值、委托号等）都只是原型的示意值，不是需求。

## 1. 意图

维护者现在核对一个交易日的实盘运行情况，必须 SSH 到两个节点读 journal、SQLite 和 Parquet
（#662 第一节）。页面上的状态又把失败、警告、维护、上游问题混在一起，长期已知警告让页面永远
是黄色，真正的新问题被淹没（#662 第二节）。导航有两套入口，最常用的数据和服务管理反而藏在
右侧工具区（#662 第三节）。

改版要做到：

1. **不登录节点也能完成每天的核对**：打开“今日运行”，5 秒内知道“今天正常吗”；任何一个
   不正常的结论都能一路点到证据（运行记录、日志片段、收据）。
2. **状态说真话**：正常、已知警告、新警告、上游问题、维护暂停、失败分得开；拿不到的数据
   显示“缺失/未知/未记录”，不推算、不补。
3. **出事时页面能指导处理**：停机闸触发、链路中断、对账不一致时，页面告诉维护者现在是什么
   状态、还差什么才能恢复，但**不在网页上提供任何改变实盘交易状态的按钮**。

## 2. 目标 / 非目标 / 反目标

**目标**
- 用统一的全局框架（左侧分组导航 + 顶部全局状态栏）重组现有约 36 个 HTML 页面，形成
  6 组 19 页（§4）。
- 覆盖 #662 第一节列出的、目前只能 SSH 查看的信息；第 9 项（安全与凭据）的展示粒度单独确认（§13）。
- 落实 #662 第二节的状态语义（§7），以及 #592、#482、#588 的验收要点（§11）。
- 白天（盘中）和晚间（收盘后）两种使用时刻都要好用；出事时（停机闸、断线）也要说得清楚。

**非目标**
- 不在网页上提供实盘交易控制：不下单、不撤单、不清除停机闸、不改风控额度、不改实盘策略参数。
- 不新增交易信号或预测模型；AI 涨停只展示已有影子榜单的结果。
- 不改变任何数据源、采集频率或真值口径；页面只消费已有或另行立项的数据。
- 不做移动端专门设计；但 390 像素视口下不能整页横向溢出（#449 回归项）。

**反目标（即使能跑也算失败）**
- 页面上出现推算、填充、插值的数据：包括把缺口两侧的点连成直线、把盘中值当定版值、
  用当前时间代替缺失的源时间、给拿不到的字段填默认值。
- 页面暗示“可以一键解决”实盘问题，或任何按钮的效果超出它的文字说明。
- 长期已知警告把整页染黄，或者新警告因为“反正一直是黄的”而被忽略。
- 页面上显示密钥、完整配置、账户资金账号、未打码的 webhook 地址。
- 页面读取拖慢交易链路（例如盘中读大快照时抢占 Linux⇄Windows 隧道，见 AGENTS.md #666 规则）。

## 5. 全局框架

### 5.1 顶部全局状态栏（从左到右）

1. **实盘状态**（实盘运行 / 已收盘 / 仅允许减仓），点击到实盘总览。
2. **停机闸状态**（未触发 / 已触发），点击到对账与风控。
3. 次要指标：QMT 在线、链路心跳、情绪温度、未处理告警数，都可点击跳页，悬停有说明。
4. 搜索（⌘K）、日期选择、当前时钟（带“盘前/集合竞价/盘中/午间休市/盘后”阶段）、明暗主题、快捷键帮助。

窄窗口规则（维护者已定方向，阈值为设计者决定）：约 1560 像素以下先收起第 3 项；约 1400 像素
以下搜索只留图标、时钟去掉阶段文字。第 1、2 项和日期、时钟始终保留。任何宽度下都不能
出现整页横向滚动。

### 5.2 停机闸横幅

停机闸触发时，状态栏下方出现常驻红色横幅：触发时间、触发者、原因、当前链路是否已恢复、
“停机闸不自动解除”，并链接到对账与风控的解除前核对清单。横幅不可关闭（#433 回归项）。

### 5.3 左侧导航

- 6 组分组导航，可收起（记住状态）。
- 徽标：数字＝需要处理的条数（告警中心的未处理数、委托页的状态未知数）；点＝该页有已知
  警告（黄）或故障（红）。告警中心确认后，徽标数字同步减少。

### 5.4 页头

面包屑 + 页名；右侧“数据截至 hh:mm:ss · n 秒前”，可暂停/恢复自动刷新、手动刷新（R）。

### 5.5 历史日期

日期选择器可切到历史交易日；切换后整页进入只读回看，顶部出现黄色“正在回看 · 只读”提示条
和“回到今天”。**原型只做了提示条，各页数据没有随日期切换**。

- **现有的按日回看能力不能丢**（回归项）：现在的成交、对账与质量、运行日志、日报
  （`/s/{session}/*`）和模拟账户（`run_session`）都能按交易日查看。改版后实盘总览、委托与成交、
  对账与风控、运行记录、模拟账户在第一期就要支持按日期取数（设计者决定，属于回归要求）。
- 打板看板沿用 11-11 设计的历史日期能力。
- 其他页面（今日运行、节点与链路、服务看板等）是否支持回看、回看多久，见 §13。

### 5.6 搜索与快捷键

- ⌘K 或 `/` 打开搜索：按类型分组（页面、委托、服务、策略、数据表、指标、告警、节点），
  方向键选择、回车打开，无输入时显示最近访问。
- 快捷键：`?` 帮助，`G` 加字母跳页，`[` 收起侧栏，`T` 切换明暗，`R` 刷新，Esc 关闭抽屉。

## 6. 页面通用规范

### 6.1 页面结构

1. **结论条（Hero）**：左侧一句话结论 + 一行说明（异常时给出可点击的问题链接）；右侧 3–5 个
   关键数字，可点击的跳页或筛选下方表格。左侧色条与图标按 §7 状态着色。
2. **主图**：标题是一个问题（如“每笔委托走到哪一步了？”），旁边 ⓘ 解释口径与数据来源。
3. **明细表**：可排序/筛选；点击行打开详情抽屉，抽屉打开时该行保持高亮。
4. **详情抽屉**：可用 ↑↓ 或 J/K 切到上一条/下一条；编号类字段点击即复制；需要跳转时给出
   “去相关页面”。

### 6.2 缺失与未知

- 拿不到的值显示“缺失”（带悬停原因）、“未知”或“未记录”，不推算。
- 图表遇到缺口时**断开**（拆成前后两段），不能把两侧点连成直线（原型在异常日发现并修正）。
- 盘中派生值标“盘中/暂计”，盘后以直取定版为准；两者不一致时标出差异，不改写盘中观测。
- 不画未来：任何图表、时间线不出现当前时刻之后的数据。

### 6.3 只读与操作

- 实盘相关的一切只读。唯一允许的“操作”是记录性的（如告警“确认已知悉”），并在按钮旁说明
  “只记录已知悉，不改变任何交易状态”。
- 研究与模拟侧保留现有写接口的能力（新建/取消研究任务、新建/启停模拟账户、策略保存为新版本、
  新建回测），每个操作都要有确认框，写明影响范围与“不影响实盘”。
- 实盘正在使用的策略版本，参数只读；修改须另存为新版本，再按 回测 → 模拟 → 实盘 推进。

### 6.4 颜色

- 行情：涨红跌绿。
- 状态：正常（绿）、警告（黄）、故障/失败（红）、待运行/未到（灰）、运行中（蓝）、休市（暗灰）。
  状态标签同时带符号（● ▲ ✕ ○ ◐ —），不只靠颜色区分。
- 已知警告用低饱和的黄并附 Issue 编号；新警告用正常饱和的黄（§7.2）。

## 7. 状态语义规范

### 7.1 状态集合

| 状态 | 含义 | 举例 |
|---|---|---|
| 正常 | 按时完成，结果通过 | 晚间任务完成、对账一致 |
| 警告·新 | 本次新出现的警告 | 调仓迟到 44s |
| 警告·已知 | 长期存在、已登记 Issue 的警告 | catalog 28 条历史缺口（#594） |
| 上游问题 | 同一上游直取字段自相矛盾（#653，`known_issue="上游数据自相矛盾"`） | daily_basic 市值与股本不一致 |
| 执行/质检失败 | 有运行记录、步骤已执行但结果失败（#592） | tushare-sync 质量拒绝 |
| 启动失败 | 没有运行记录或启动阶段失败（226/NAMESPACE 等），不为它造运行记录（#592） | unit 启动失败 |
| 维护暂停 | 有界维护中暂停（#482） | 发布期间暂停 timer |
| 调度关闭 | timer 被有意停用（#482） | 停用 Live 期间的组件 |
| 常驻进程停止 | 常驻服务不在运行（#482） | health-observer 停止 |
| 待运行 / 未到 | 计划时刻未到 | 晚间任务在盘中显示为待运行 |
| 运行中 | 正在执行 | 盘中采集 |
| 休市 | 非交易日不运行 | 周末 |

### 7.2 已知警告与新警告

- 页面的整体结论只被**新警告、故障、启动失败**染色；已知警告单独计数（“1 项已知警告”）并
  链接 Issue，不把结论条染黄。
- 已知警告的判定来自显式登记，页面不自己猜。**设计者决定**：仓库内维护一份受管清单
  “检查稳定 ID → Issue + 基线”（基线＝登记时的违规数与样本指纹）；数据层已有的 `known_issue`
  标注（如 #653）同样计入。判定规则：违规数不超过基线且没有新样本 → 已知警告；违规数超过
  基线或出现新样本 → 新警告（例如 28 条变 29 条，算新警告，并显示“比基线多 1”）。登记、
  调整基线都走代码评审，页面不提供修改入口。
- 历史上真实发生的失败照常显示为失败，不因语义调整而降级（#482）。

### 7.3 盘中与定版

- 盘中值（打板看板、AI 涨停“盘中进展”、昨日涨停今日表现等）标“盘中/暂计”。
- 收盘后的直取定版到达前，“盘后定版”视图如实显示“还没有生成”，不拿盘中值冒充。

## 8. 各页规格

以下列出每页的内容与需要的数据。“数据现状”一栏是设计者根据当前代码与 Issue 的判断，
实施前须逐项核实（§12）。

### 8.1 今日运行
- 结论：运行中/已收盘/停机闸已触发 + 需要留意的项（每项可点）。
- 关键数字：账户总资产（原始观测，不叫收益）、上证指数、涨停/跌停与封板率、链路心跳。
- 阶段条：盘前 → 竞价 → 盘中 → 收盘 → 晚间任务，各自状态与进度。

## 10. 性能、刷新与读取边界

- 自动刷新默认 5 秒，可暂停；但**刷新频率不能快于数据本身的发布间隔**（打板看板快照 15 秒）。
- 盘中读取全量快照的接口要遵守 #666：读取频率不快于发布间隔，失败或过慢时退避，研究/展示类
  读取给实盘和模拟让路；多个浏览器标签不能各自独立打满隧道（设计者决定：服务端缓存同一份快照，
  前端只读缓存）。
- **Web 不按请求直接读 Redis**（设计者决定）：顶栏的 QMT 在线、心跳等状态取自 health-observer
  已采集的本地结果（或服务端统一缓存），每个页面的 5 秒刷新只读这份本地结果，不增加隧道负载。
- **读取权限**（设计者决定，依据 AGENTS.md 最小权限规则 #479 / #487）：Web 保持现有最小权限，
  不加入 systemd-journal 组、不直接读节点白名单或部署记录。journal 片段、组件版本与发布记录、
  systemd 状态、Windows 节点资源与 QMT 状态，都由专门的采集器写成快照，放到 observers 可读的
  位置，Web 只读快照。
- Web 发布会重启 qsys-monitor：安排在收盘后，不占交易时段。
- 回归项：服务管理页连续请求约 8–10 秒（#448）、数据目录与表详情约 30 秒（#442）必须解决。
  设计者决定的目标：结论条与列表接口在常态下 1 秒内返回；重计算放到后台任务并缓存。
