## 实施约束

1. 当前质量与历史结果分开。旧失败留存；当前输入变化而未重验时显示“输入已变化，待重验”，
   使用缺证据门禁，不把旧red直接改green，也不把旧green继续用于新输入。TTL仍独立生效。
2. 证据绑定检查真正读取的源/目标及范围。先逐项审查cutover_health的实际query调用，
   不能只从目录mtime、最新字段批次或概念依赖图推断已验数据版本。valuation的直接输入是
   Tushare对应列与valuation_daily；名称全区间、分钟日/年有效分区等必须按各自读取语义处理。
3. 首版可绑定物理文件身份（相对路径、dev/ino/size/mtime_ns）的规范指纹，明确这是版本身份，
   不是逐值一致或独立来源的证明。独立替换即使内容相同也须重验；缺失/新增分区同样失效。
   文件选择须复用实际查询的日分区优先逻辑，不能同时统计被遮蔽的年分区；不扫描全仓内容哈希。
4. 检查前后核对绑定输入。变化时不得把结果作为新输入的成功证据，需明确失败/缺证据。
   既有真实warehouse写锁继续使用，不为修复引入并行生产写者或循环重放维护任务。
5. 表、关系证据各自绑定。字段检查成功不替代表/关系；关系绑定双方输入，避免单方更新后仍绿。
   存储格式须显式版本化，保留旧结果逐值与重复次数；旧无绑定证据不得被暗认为当前有效。
6. 展示同时说明“历史检查结论”与“是否适用于当前输入”，不把技术指纹塞进普通用户操作流程。
   页面与服务检查/日报等实际消费者须联查，不能只修一个页面聚合函数。

## 受控刷新与发布顺序

先实现兼容的证据生产/读取与有意义的离线回归，再走正常CI/test/PR和组件发布。
新记录必须能被当前生产消费者发现读取，更新消费者前先用真实UID/current venv验收。
无绑定旧记录的过渡行为、回退时读取兼容性与质量目录精确写权限须提前确认，不能发布后补想。

自动刷新应接在完成派生与canonical写后对账的收盘成功路径之后，明确ServiceRun独立步骤与
资源预算，不能在源事实成功但派生中断时声称整个批次已验证。现有19:40 catalog保留；
若选择只做版本失效而不在采集器增加全量计算，应明确显示等待此任务的验证窗口与门禁。
不得为了缩短等待重跑采集，也不在尚未收盘时采集当日行情。

本次#562安装已经完成；不能把其人工新证据或19:50只读观察器当作#561自动刷新代码。
需要新的组件发布时，继续核对可信控制器及节点规格；不能扩大停机维护例外来绕过交易门禁。

## 验收矩阵

- 相同版本、TTL内的绿/黄/红保持原判定；TTL过期仍缺证据。
- 目标替换、源变化、文件增删、有效分区切换后，历史结果不变，当前状态待重验。
- 只有字段新批次，或只有无关数据集变化，不冒充表级新验证；无关变化不应无界失效全仓。
- 检查期间输入改变不发布适用于新版本的成功证据；失败留存且不自动重放写操作。
- 新重验成功、真实失败、仅warning分别正确传播；表与关系双方版本分别验证。
- 原始旧表、旧消费者、混合新旧记录与重复历史行兼容；真实只读UID和实际unit沙箱均验收。
- 生产验收分别记录CI、测试部署、三方发布、人工批次、下一自然任务，不合并为“全部恢复”。

尚未实现的代码、最终持久化格式和生产门禁均不以本文视为通过。


## 10-29实现与受控刷新选择

候选在dataset_checks/relation_checks各加nullable string input_version，记录版本1、对象集、
日期范围、freshness读集、外部响应摘要和物理文件指纹。旧文件的此质量元数据保持null；
所有旧列逐值保留，旧读取器按原schema投影仍可读。指标字典同步登记两项运行元数据，
总字段从442变444；不把schema变化漏登记，亦不改变市场事实或原质量规则。

读集使用实际对账来源而非builder的推测依赖；目标freshness检查实际遍历的文件也绑定。
QMT日/年文件选择与真实query共用函数，付费年shards/day文件和manifest按实际选择绑定；
分钟覆盖源及Tushare日线的条件性依赖采用保守并集，不能漏掉源候选出现/消失。
trade_cal直取响应单独绑定其JSON SHA；本地消费者不再次请求API，外部新事实仍由原TTL和
下一次正式重验发现。版本身份不等于独立真值证明。

检查前保存绑定，落表前重核；漂移抛错，不发布适用于新输入的成功证据。Web当前聚合、
关系当前状态与规范切换门禁均核验版本，旧无绑定/输入改变返回gray待重验；原历史状态和
原违规数不改。规则页明确历史结论的时点，不把历史表格冒充当前健康。

本轮保留19:40完整catalog作为受控刷新窗口，不向Tushare主链追加全量分钟计算。
canonical新版本发布到catalog完成之间显示待重验，不能自动解除下游门禁。生产先升级
catalog并完成人工真实输入新证据，再升级Web；日报/service-checks实际只消费字段层与
ServiceRun，不因本项升级。其他未发布的cutover消费者不算现场验收。

必要controller v37只允许原本active且已安装的Web在既有停止Live/稳定绑定/KILL/主库
前后保持条件下升级，八peer连续性、HTTP恢复均须通过；拒绝新装或启动inactive Web，
其他组件保持原入口门禁。此项与catalog联合按#561正常CI/test/PR发布，生产安装仍待验收。

回归覆盖物理替换（含值不变）、源/目标增删、无关表不失效、日分区覆盖年文件、旧schema
与旧投影兼容、TTL、对象/范围防串用、关系双方绑定、真实验证过程漂移拒绝、页面当前灰与
历史红并存，以及实际controller记录validate_record与仅Web重启。全量和生产证据以Issue为准。
