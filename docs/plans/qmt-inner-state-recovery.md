## 2. 2026-10-25原生账户只读探针

本阶段与此前“账户调用0”的纯市场诊断分开。探针仅调用正式查询函数，没有注册交易回调、
发委托、撤单、设置交易账户、激活模型交易或执行下载。编辑器调试与真实交易入口分开。

从旧代理实际引用的私有runtime读取连接标识，在Windows受限审计根绑定源码；
账号不在工具输出、Git、Issue或不含账号的模板中。先查询ACCOUNT，只有返回记录的
m_strAccountID与该私有标识逐值匹配，才继续其余查询；不匹配/缺字段/空结果直接停止。
私有绑定源码归一化账号赋值后，与不含账号的模板SHA逐字节匹配，未追加其他执行逻辑。

| 正式调用 | 实际返回 | 证明范围与限制 |
|---|---|---|
| get_trade_detail_data(..., STOCK, ACCOUNT) | list，1条；账号精确匹配 | 取得身份正对照；未见本探针所查m_nStatus/m_strTradingDay，不能据此证明柜台同步时点 |
| 同接口POSITION | 空list | 只记录当前客户端结果，不认定券商空仓或查询完整 |
| 同接口ORDER | 空list | 不认定无活动委托，也不裁决#535故障撤单投递结果 |
| 同接口DEAL | 空list | 无真实成交字段/唯一标识样本，不验证费用或去重 |
| get_history_trade_detail_data(..., POSITION, 20261023, 20261023) | NameError | 当前实际环境未解析到此全局函数，未完成历史查询 |
| 同历史接口ORDER | NameError | 不将错误当作历史无委托 |
| 同历史接口DEAL | NameError | 不将错误当作历史无成交 |

[官方交易查询文档](https://dict.thinktrader.net/innerApi/trading_function.html)说明当前查询及
历史查询的调用签名。文档存在不保证本券商/版本暴露该能力，未通过SDK或外部路径替代。
这里也没有把股票ACCOUNT未提供某两个所查字段认定为券商缺少必需字段；仅说明本探针
未得到可证实同步时点的信息。查询返回不等于柜台事实新鲜、完整。

共9条协议记录，7次查询尝试、4次正常返回；3次NameError不算已完成查询。
字段存在性在空列表上记null，成交唯一键判断保持未知，不以空集的“全部满足”当验证成功。
公开结果只有条数、字段存在性、身份匹配与错误类型，不输出账号、金融金额或交易标识值。

## 4. 恢复需要的事实

完整场景矩阵见[计算输入与恢复契约](../reference/qmt-inner-input-contract.md#状态恢复验收矩阵)。
这次只读查询没有完成其中任何一项完整恢复验收。

| 必需事实 | 当前缺口 | 继续推进条件 |
|---|---|---|
| 逐lot分支、入场价、取得日及FIFO核销 | 聚合持仓不提供等价账本；无非空样本 | 正式内部持久化，或可无歧义重建的完整回报与归属证据 |
| 发送前后崩溃的订单状态 | 当前ORDER空且完整性未知 | 可区分已发/未发/未知，未知不补发 |
| 稳定成交标识与跨运行去重 | 当前DEAL空，历史全局函数不可用 | 真实非空样本、标识范围/稳定性、覆盖与重复回报验证 |
| 部分成交、冻结与累计费用 | 未取得相关样本 | 逐回报数量与委托累计费用对照，不能重复计最低佣金 |
| 人工/他模型隔离 | 仅查询整账户，没有归属样本 | 正式策略名/备注/订单身份语义与历史保留确认 |
| 跨模型/客户端重启恢复 | ContextInfo自定义属性不跨模型重跑 | 券商正式状态机制及真实恢复验证，不能使用内存set证明持久化 |
| 首次空仓切换 | 当前查询空，柜台新鲜度/完整性未知 | 最新真实账户核对、活动委托与pending闭环、唯一交易所有者 |

旧适配器提交策略名qsys及client_order_id作为备注，分支tag不作为独立券商参数传入；
不能直接假设查询备注就恢复了tag。应实测实际格式/保留范围和历史覆盖，不拼接猜测映射。
