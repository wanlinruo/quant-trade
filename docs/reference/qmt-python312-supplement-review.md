## 对现有准备材料的直接影响

指南限定`ContextInfo.get_market_data`、`get_financial_data`、`get_top10_share_holder`
在多股票、多日期场景由Panel变为DataFrame：日期为index，columns为股票/字段两级索引。
旧`major_axis/minor_axis/major_xs/minor_xs`访问需要适配；股东接口的单元格仍为list。
映射按股票、字段和日期标签取值，不能假定返回列序与请求顺序一致。

当前历史准备主要使用`get_market_data_ex`，指南没有列出它或`get_raw_financial_data`，
因此不据此全局改写所有接口。普通dict的`.items()`不受Panel迁移影响；指南常见错误表
也不能作为删除所有`.items()`的依据。离线参考环境pandas3.0.5的DataFrame仍有可调用的
`items`，这只是反例，不是目标QMT环境版本证据。

现场已测运行时仍为Python3.6.8/pandas0.22.0/NumPy1.19.1。随包存在PythonFormula312.dll
只证明文件存在，不证明库已下载、加载或模型已运行。3.12有望减少与项目Python≥3.11的
语法兼容成本，但不解除沙箱文件/网络限制，也不自动修复崩溃、历史限价、历史股票池、
停牌覆盖、状态账本或成交去重。

原生KV目前只证实19字节合成值的一次写读与同客户端模型重跑。随包`fun.xml`描述服务端
存取及返回码，但没有容量计数、编码、加密、多key原子性或策略/账户隔离保证。跨客户端
读回尚待执行；不能把重启成功当作持久化通过，也不为评估文档新增大值写入。

## 建议执行顺序

1. 先在当前已重启的客户端、原诊断模型中执行一次既有key的GET，不新增save，不读账户或交易。
2. 只读检查模型设置的实际选项、库包来源/容量及C盘余量，准备保留py36和现有模型/配置的切换步骤。
3. 将保存运行库设置、客户端重启的具体方案提交维护者确认，再实施运行库切换；指南要求新增策略，
   不能假设现有模型会自动迁移。
4. 新增无交易模型实测sys/pandas/NumPy版本及各实际使用接口的类型、索引、空值、单位与时基。
   对#538现金/送转/配股及停牌窗口做同输入、同as_of精确对照，保持独立量因子、原始成交额与冻结阈值。
