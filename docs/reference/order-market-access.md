# 北交所只行情、不新开仓（#589）

维护者2026-11-03明确：当前账户无北交所交易权限，策略不交易北交所，市场情绪仍需
保留北交所行情。本项关联[#589](https://github.com/wanlinruo/quant-trade/issues/589)、#588。

`live.safety.check_order_market`是无I/O的固定交易限制，供Live/Shadow/Paper订单入口、
Windows ExecutionAgent及XtQuantAdapter共享。它不查询券商、不自动赋予其他板块权限，
不影响候选池或市场行情范围。代码里的沪深身份放行只代表通过本项限制，仍须经过全部
账户、KILL、时效、仓位、资金、停牌、限价及策略资格约束。

- 规范`六位代码.SH/SZ/BJ`之外的订单身份明确拒绝，不默认按主板处理。
- 买入`.BJ`及已知北交所4/8/92号段均拒绝，避免错误后缀绕过；`000920.SZ`不误伤。
  这不是用号段生成证券主表或市场事实，仅是对新开仓的保护性拒绝。
- Live/Shadow在构造风险报价上下文前拒绝，并产生Reject；Shadow没有意图入流。
- Paper提交时拒绝；恢复的旧买单在匹配报价时也检查，不能通过restore绕过后新增仓位。
- ExecutionAgent在commissioning等分支和券商幂等查询前拒绝并发布Reject；即使绕过该代理
  直接调用XtQuantAdapter，仍在SDK导入和券商下单之前拒绝。
- 拒绝的是新开仓：本地去重台账或恢复的Live挂单已证明受理的历史命令重传直接保留，
  不发新券商调用，也不改写为拒单；回报照常轮询对账。Paper历史部分成交只拒剩余量。
- 合法北交所卖单继续受已有持仓、可卖量等约束；撤单与查询/回报对账入口不变。
  不删除历史持仓、挂单、成交或自动重放旧命令。

离线测试走真实submit/run_once/place_order入口，报价/幂等查询/券商place探针设置为禁止
调用。覆盖920新号段、错误后缀、未知身份、普通000920、commissioning绕过、Paper恢复
挂单以及撤单/适配器卖出路径。测试通过不代表生产已安装，尤其不能启动停用Live或旧
Windows交易代理来验收。本轮发布状态以#589最新记录为准，账户权限未改变。
