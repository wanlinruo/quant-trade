# QMT 内置迁移：计算输入与恢复验收契约（#533）

承接 [迁移方案](../plans/qmt-inner-strategy-migration.md) 与
[Issue #533](https://github.com/wanlinruo/quant-trade/issues/533)。
这是下一阶段适配器的输入和验收要求，不是已实现的数据通道。
维护者已明确：数据与全部指标只能基于QMT原生数据在沙箱内生成，禁止外部注入。
此前考虑的模型参数录入盘前真值路线撤销。跨重启正式状态机制仍待实测。

## 计算核心的范围

`qmt-inner-decision-core.py` 包含当前 `params/gate/allocation/exits/entry` 的纯计算函数和常量，
以及 `selection._stock_factors` 的10日收益/60日高点距离计算。
本地生成器 `build-qmt-inner-core.py` 从源码 AST 提取，移除类型注解与说明文档，
把冻结 dataclass 输出记录转成不可变 namedtuple；函数中的算术、比较、分支与默认值保留。
入场函数体仍直接取自原AST，配合内存History对象替代其使用的少量Polars列/窗口操作。
生成物只有标准库 collections 依赖，语法按 Python3.6 解析；这不是在 Python3.6 解释器或
江海新版上的执行证据。6个原文件及历史输入容器的SHA-256写进生成物，避免手抄阈值和双份算法各自漂移。

本机命令：

```bash
uv run python docs/reference/build-qmt-inner-core.py
uv run python docs/reference/build-qmt-inner-core.py --check
uv run pytest tests/scripts/test_qmt_inner_entry_core.py tests/scripts/test_qmt_inner_decision_core.py tests/scripts/test_qmt_inner_readonly_probe.py -q
```

生成器只在本地开发机运行，不能复制到 QMT 中。生成物没有 init/handlebar、行情接口、账户、
timer、Store 或委托接口；不能独立承担策略，也没有实现初始化完整性门禁。
allocate 的 `ORDER_SUBMITTED` 是原计算函数的结果标签，**不是发单或受理回报**。
候选池、全市场生态计算、分支路由、逐lot记账、T+1和风控适配仍未移植。
其中LOW_MAIN的0.020附加竞价量过滤仍在selection._route，不能将check_low_open为真
直接当作整条入场路线已通过；LOW优先且不回落HIGH的路由顺序也仍由后续适配器承接。

### 历史输入的有效范围

`History(columns)` 来自本地材料 `qmt-inner-history-input.py`，生成器将其源码并入计算核心。
它不连接QMT、不读取文件、不提供外部输入通道；未来仅由经过实测的沙箱原生适配器组装。
当前测试中的手工数据全部是离线夹具，不是可以注入QMT运行时的盘前数据。

- 必须明确提供open/high/low/close/volume/amount六列，长度相同；只接受有限的Python数值，
  拒绝None、NaN、无穷、布尔和字符串。缺失报错，不填值，不做类型或单位兼容转换。
- 数值序列复制为tuple，原列表后续修改不影响本次计算。tail只取指定尾部，不排序、不补行。
  数据日期、升序、PIT、复权和单位仍须由后续原生适配器确认，容器不推断这些事实。
- 入场差分限定上述完整有限输入域；现有Polars聚合可能接受的缺失输入不宣称等价。
  拒绝缺失是输入完整性检查，不把其余数据改写成默认值。
- HIGH的现有公式以规范日线volume为手、amount为元，市值为亿元；竞价量与昨日量须同单位。
  合成夹具验证的是现有规范单位下算术一致，**没有证明QMT原生接口恰好使用这些单位**。
  新版单位未实测前，不将其原始DataFrame直接交给该核心，也不通过股/100等兼容转换凑输入。
- 60日相对位置、从倒数第3天寻找前高、放量严格大于0.9倍、HIGH竞价量严格模式及个股
  10日/60日因子与原函数逐字段对照。测试覆盖的require_auction_volume=False仅用于
  保留既有函数语义，不授权将当前生产的严格模式关闭。

## 生产基线与费用、额度的区别

2026-10-23 21:04 从实际 Live release `34c7b7b` 只读取样，13个关键模块逐文件SHA-256
与当时开发树一致，见 [基线清单](qmt-inner-production-baseline.json)。它包含选股、策略、
入场、Gate、分配、退出、阈值、feed/market_feed/query、runtime/store/fill_tracker。
记录包含公开代码指纹与筛选后的策略/风控/费用值，不含真实账户、凭据或完整配置。
这是历史采样，不能代替最终切换前的现场核验。

以下值必须分开，不能为了“统一”而改动其中一套：

| 项目 | 当前有效值或公式 | 对移植的要求 |
|---|---|---|
| 实际配置佣金模型 | commission_rate=0.000075，min_commission=5 | 真实费用/回报对账独立实现；配置模型不等于已取得首笔自然股票实收费验收 |
| 定量准备金 | max(5, budget×0.0003)+budget×0.00001 | 原CASH-SAFE公式，不能改成实际配置佣金率 |
| 委托保护价缓冲 | entry_price_buffer=0.03 | 原函数默认0.002不是当前有效参数，适配器须显式传入 |
| 定量缓冲 | sizing_price_buffer=0.005 | 与委托保护价分开，不能合并成3% |
| 资金上限 | enabled_capital=10000 | 独立于券商账户总资产与可用余额 |
| 默认单标的预算 | runtime按 min(enabled_capital, day_start_value×0.05) 注入 | 不能因为纯allocate默认max_budget=None就给一只候选全部账户现金 |
| 单笔委托上限/日损失 | max_order_value=10000，max_daily_loss=0.02 | 属于runtime/risk约束，不包含在纯allocate中 |

## 输入对象与来源约束

数值单位和可见时点必须在适配边界确认；下表描述的是现有计算函数的输入，不声称新版
QMT返回同名字段或相同单位。新版接口列名、单位和权限在探针实测后才允许写映射代码。

| 输入 | 形态/语义 | 必要证据 |
|---|---|---|
| tag | LOW_MAIN/HIGH_MAIN/LOW_CHINEXT/HIGH_CHINEXT | 来自现行分支路由；未知分支不由适配器猜测 |
| env | dict，T-1五个生态字段 | 字段分别为index_ma20_slope_5d、prior_limitup_nextday_return_mean、market_median_return_1d、touched_limit_up_count、market_advance_ratio；全A与滚动窗口保持 |
| stock_factors | dict，stock_return_10d、distance_to_60d_high | 同一已确认历史、复权、窗口和可见时点 |
| candidates | 有序(symbol,tag)列表，已通过入场及Gate | 顺序和权重归一化范围保持；纯core不能自行构造候选 |
| cash/max_budget | 策略可用现金及单标的预算，元 | 由等价runtime算出；保留资金冻结/持仓占用及风控，不能直接使用整账户余额 |
| opens/limit_ups | symbol→价格，元 | QMT原生最终竞价成交价及当日限价直取事实；字段名、单位与业务日须探针验证，不按比例自算限价 |
| recent_closes | 按日期升序的历史收盘序列 | 截至上一交易日，锚点一致；动态MA5在函数中取最后4根和当前价 |
| last_price | 检查点当时可见价格 | 时间戳、新鲜度、停牌状态和缺失路径须验证，不能用未来收盘价补齐 |
| entry_price/tag/acquired_on | 原策略lot的成交价/分支/取得日 | 来自真实成交与策略账本，不能仅凭券商聚合成本恢复 |

首板候选、ST、限价、停牌、退市整理期、上市日期、估值与复权历史均须按迁移方案用QMT
原生接口的直取事实/确定性纯派生实现。Linux历史与Tushare仅用于外部研究/对照，不进入
内置运行时；禁止手工传候选/因子/状态快照。允许在沙箱内由已验证同日价格和股本做确定性
市值计算，但不能以当前股本代替历史股本，不把“纯派生”当作近似估算或填补缺失许可。
换源差异与算法差异分开归因，不改变冻结S6/S7阈值。

官方通用文档已提供get_instrument_detail、get_his_st_data/get_st_status、板块成份与原始
财务接口；江海新版已取得部分原生样本，完整覆盖和语义尚未验收，详见迁移计划§0.1。
ST历史接口依赖客户端历史数据，
空响应不能单独证明非ST；合约股本字段存在不同拼写，诊断只打印原始字段不合并猜测。
原始财务接口优先核对announce_time，避免report_time造成前视，也不采用逐交易日填充
接口绕过缺失。参见[迅投行情文档](https://dict.thinktrader.net/innerApi/data_function.html)。

### 原生数据仍须证实的关键覆盖

| 项目 | 目前能确定的范围 | 后续证据要求 |
|---|---|---|
| 昨日首板/触板 | 合约信息文档给出当日UpStopPrice，不等于已取得历史限价 | 昨日及前日正式历史限价或等价原生事件事实；不拿今日限价比较昨日收盘，不按比例重建 |
| ST | 两种接口取得000004.SZ历史ST/*ST区间，600000.SH仍为空 | 同时验证已知ST/非ST、变更区间端点和缓存覆盖；空dict不能独立证明非ST |
| 退市整理期 | ExpireDate表示退市/到期日，不等于整理期起始状态 | 正式状态事实及生效时点；不能由名称或退市日推定整理期 |
| 全A历史范围 | 沪深A股默认5225个代码、带原生历史时间为空；上证50正对照50个 | 核验沪深京/科创/ST及已退市成员在T-1和滚动窗口的覆盖，避免当前名单回溯偏差 |

| 复权 | 截短end_time未改变重叠前复权价格；送转样本39根复权量均等于原量 | #538适配as_of锚点及独立股本量算法，先验证事件覆盖和舍入；空因子不填1，不用价格因子调量 |
| 竞价/单位 | 历史tick补充后，早期177条、09:25:10前09:25:02一条及连续交易对照3条 | 分别验真实时报价新鲜度、完整覆盖及volume/盘口量/amount单位；不转换股手、不用最终竞价填早期快照 |

这些是待验证缺口，不是已经断言QMT不支持。可用性要以江海新版正式接口实测为准；
在确认前只移植已知纯计算，不实现依赖未确认字段的选股数据适配，不把公开样本通过写成历史全覆盖。

## 规范输入复权算术（#538）

本地锁定Polars1.44.1，实测`Expr.round`默认`mode='half_to_even'`，
`[0.5, 1.5, 2.5, 3.5]`舍入后为`[0, 2, 2, 4]`，与
[官方round接口说明](https://docs.pola.rs/api/python/stable/reference/expressions/api/polars.Expr.round.html)
一致。原`HistoricalFeed.get`先按收盘可见时刻裁剪，再取返回日线末根的累计价格/股本因子
作锚点；价格乘本日价格因子/锚点价格因子，量乘锚点股本因子/本日股本因子后舍入到整数，
成交额保留原值。任一累计因子缺失仍应返回null，不补1。

先移植上述已确认的规范输入算术。函数所需收盘时间、逐日累计因子均须由后续原生适配器
验证和生成；它不解析七字段原生除权事件，逐日因子映射尚未实现，也不证明原生日历、事件覆盖、
单位或公告PIT已通过。此项纯计算验证不授权向沙箱注入外部动态数据。

准备核心新增`forward_adjusted_columns(columns, bar_close_times, *, as_of,
cum_price_factors, cum_share_factors)`：同一时基的显式整数时间戳与逐日因子等长对齐，
返回`as_of`可见前缀的六列副本，不排序、补行、转换时间或改成交额。收盘时刻含边界；
无可见bar则返回空列，锚点取返回前缀末根，未来值不参与计算。函数不生成交易日历，
不能将原生日线午夜标签直接当作已验证收盘时刻。

原值和累计因子允许显式None，缺价格因子只使对应OHLC为None，缺股本因子只使量为None；
锚点缺失则相应整列为None。返回的可空列供质检；传给既有History时不完整数据仍拒绝，
不存在以缺失量或因子1兜底的路径。非有限值、非正因子、时间乱序/重复、长度错配及
量超Int64范围明确报错。累计因子并非此函数计算或证明完整，原生映射仍由#538后续承接。

## 缺失与默认值的边界

1. 现有Gate的UNKNOWN_ALLOW与三值AND/OR是需保持的算法行为；同输入差分包含显式None、
   NaN和无效字符串，不用“更保守”替换冻结逻辑。
2. 数据通道是否真实接通、日期是否正确、所需字段是否存在，属于适配器启动完整性门禁。
   全部传空dict也能计算出UNKNOWN_ALLOW，**并不证明允许启动交易**。
3. 测试包含缺限价、未知tag和空历史等既有函数分支，用于发现移植差异；这些合成输入
   不证明生产输入合法，更不是允许新源缺数据时用默认值放行。
4. 接入层必须保留“未接通/字段缺失/源明确返回null”的区别，并按原调用方语义处置。
   当前纯core不含该接入层，因此不能进入实盘。

## 状态恢复验收矩阵

当前 `strategy.on_fill` 用真实买入成交维护分支lots，卖出FIFO核销；适配器提交给券商的
参数含qsys策略名与client_order_id，分支tag不作为独立参数传给券商。因此不能假定
查询到持仓/备注就已经恢复tag、取得日和成交去重。新版正式接口是否能补足信息仍未验证。

下表是必须完成的验收场景，**不是本轮已通过的测试**：

| 场景 | 恢复后的要求 | 缺证据时的处理 |
|---|---|---|
| 空仓且无活动委托的首次切换 | 以最新柜台/客户端事实核实，无旧代理可重新发单 | 不以早先Linux空库作为当前券商空仓证明 |
| HIGH/LOW持仓跨日 | tag、入场价、取得日、可卖数量逐lot保留 | 不能依据当前价格或盈利状态猜分支 |
| 同一证券多批买入/部分卖出 | FIFO与原lot账本逐值一致 | 聚合持仓相等不能替代lot一致 |
| 发送后、回报前崩溃 | 确认是已提交/未提交/未知；禁止重复补发 | 结果未知则暂停自动续跑并人工核对 |
| 成交已到、记账前崩溃 | 按真实成交唯一标识只应用一次 | 无稳定标识/历史缺页则不自动补账 |
| 同一成交重复推送/历史重查 | 状态和费用不重复累加 | 不把模块内set当跨进程去重证据 |
| 一单多次部分成交 | 数量、冻结、累计费用增量与终态一致 | 原最低佣金按委托累计，不能逐回报重复收取 |
| 撤单失败/拒单/未知状态 | 回报不足时明确未知，不虚构已撤/已成 | 保留未决，不重新占用同一预算下另一单 |
| 人工成交/其他模型持仓 | 有明确归属，不挪入本策略lots | 不根据同一证券代码直接接管 |
| 断线后缓存/客户端重启 | 客户端快照新鲜度及历史覆盖可证实 | 缓存可查询不等于柜台事实已完整同步；已测ContextInfo自定义标记不跨模型重跑保留，正式持久化仍未证实 |
| 双模型/重复启动 | 单一管理者，重复事件不发第二单 | 当前无共享持久锁证据，不宣称已解决 |
| 持仓未知且控制链路不可用 | 客户端停止/人工处置路径已实测 | Linux kill/Redis开关不能充当内置模型急停 |

首个只读探针不查账户和历史成交；上述项目需正式数据接口探针、允许的状态机制和新版
真实运行证据后，再接入离线恢复夹具。当前不编造字段映射，也不为验证执行真实交易或重启。
