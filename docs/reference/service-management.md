# 服务管理与每日服务质检

页面：监控台右上角「服务管理」（`/services`）。代码：`src/qsys/ops/services.py`（服务清单与运行记录）、
`src/qsys/ops/service_checks.py`（质检）、`src/qsys/web/service_views.py`（页面）。

## 为什么做

2026-09-17 用户提出：每天有哪些定时任务、访问哪些接口、写哪些表、执行得怎样，此前只能登服务器查日志。
同时 D-18 查出原「到货检查」对停牌、名称快照、分钟线、采集日志只是名义覆盖。两件事合并：
**任务自己写运行记录，服务质检按记录与直取源核对产出，结果挂在服务管理看板上。**

月度任务不进「每日执行看板」（否则非执行日天天判漏跑），单列在「月度任务」看板里，
非执行日显示为不适用。

常驻服务（模拟交易、影子盘、监控网页、Redis 隧道、Windows 行情网关与执行代理）只显示进程状态与心跳。
Windows 进程看门狗每 5 分钟执行一次，属于周期守护任务：不占「每日执行看板」的日期格，
在「进程状态」中通过只读 SSH 查询 Windows 计划任务。`Ready`/`Running` 且上次结果码为 0
显示正常；`Disabled` 或上次运行失败显示异常；Windows 不可达显示未知。

## 运行记录

- 目录：生产 `/home/ubuntu/qsys/var/service-runs/YYYY/MM/DD/<服务>-<HHMMSS>-<pid>.json`。
- 一次执行一个文件，每步结束原子落盘；进程被杀时记录停在 running，超过该服务最长运行时间显示「已中断」。
- 写记录出错只打日志，不影响任务与退出码。
- 取代原先空转的 `ingest_log`（Tushare 同步从未写它；旧记录保留不删）。

## 质检项（`CHECKS`）

| 任务 | 检查 | 期望来源 |
|---|---|---|
| 盘前涨跌停价 | 开盘前取到当日涨跌停价 | 盘前运行记录 |
| 每日归档 | 竞价逐笔到货、分钟线到货、**首根有成交**、全天成交量对日线（≤1 手） | 首板次日候选（与下载清单同源）扣掉直取停牌；Tushare 日线 |
| Tushare 同步 | 退市整理期池与 namechange 独立重算一致；日线到货（≥ 上一交易日 98%）、涨跌停价/ST/估值覆盖日线、派生标记覆盖主板创业板科创板日线、停牌采集成功、涨停列表非空、沪深300、主表已更新、市场广度、增量质检阻断项 | Tushare 日线；同步运行记录（停牌当天可以真为 0 只，只认采集成功） |

「首根有成交」2026-10-04 取代了原先的「每只 241 根」。旧判据对 QMT 的昨收价填充
完全失明——**填充正是满足它的手段**，它把不足 241 根的日子补齐到 241；而首笔成交晚的
标的在正确数据下本来就不足 241 根，旧判据反而会误报。见
`docs/reference/qmt-range-query-padding.md`。

看板规则：任务失败或未运行显示原状态；任务成功但质检失败显示「质检未过」，质检警告显示「质检警告」。

## 退市整理期池（2026-09-17，第 3 步）

- 表 `delisting_pool`：每个交易日处于退市整理期的标的。派生自 `name_history`（Tushare namechange）
  `change_reason='退市整理期'` 区间，剔除 `instruments.delist_date` 早于当天的已退市标的
  （namechange 常不登记已摘牌股票的整理期结束日，不剔除时池里 153 只全是早已退市的）。
- **候选池剔除的唯一出处**：`WarehouseQuery.delisting_symbols` 只读这张表，原先在查询层直接过滤
  namechange 的逻辑已删除。池子未覆盖的日子显式报错，不返回空集。
- 每晚同步的派生步骤重建近 150 个交易日并**多建下一个交易日**（次日开盘前选股要用）；
  覆盖区间记在每个年分区的 Parquet 元数据里，用来区分「当天没有」与「没建」。
- 上线回填：`scripts/build_delisting_pool.py --start 1990-01-01`（测试快照 8.5 秒，3,362 行，单日最多 34 只）。
- 验证：测试快照 2000-01-04 ~ 2026-09-17 共 6,473 个交易日逐日对照旧逻辑，新池只少掉「当天之前已退市、
  前一日无日线」的标的，候选池结果不变（bad=0）。
- 数据管理页显示池子已构建到的最后一个交易日的名单；服务质检独立重算核对。
- `name_snapshots` 停写，已有 4 天数据保留，指标字典标为冻结。
