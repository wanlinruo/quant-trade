### 5.1 来源核验结论（2026-09-21，生产只读）

结论：**12 只证券（含 `920305.BJ`）的 194,487 行全部来自余哈哈付费源 2026 年
按交易日 1 分钟 CSV，`source=paid` 的标注是对的**。初次抽查时说“11 只出现在聚宽
覆盖表中”只在证券层面成立；按标的日比对两者**零重叠**（付费 807 个标的日、聚宽
444 个，交集 0），逐键交集也是 0。格式也不同：越界文件每天 241 根、从 09:30 开始、
带 `factor`；聚宽每天 240 根、从 09:31 开始、无 `factor`。因此不需要迁移或隔离。

证据链，每一环都做了逐键逐字段比对：

| 环节 | 证据 | 结果 |

### 5.3 门禁查出的缺陷：卖家 2026-03-03..03-11 分钟成交量错误

24 个粗大偏差全部是成交量问题：000004.SZ 6 个、002808.SZ 5 个、002898.SZ 7 个、

1,641,468,800 股，日线 212,942.46 手（21,294,246 股），成交额两者一致
（120,235,175 元与 120,235,178 元）。

同一时间段对付费暂存区做全市场只读核对，问题不限于这 12 只：

| 交易日 | 可比证券 | 成交量偏差 >5% | 其中成交额也 >5% |

## 6. 备份与恢复

现场有约 831 MiB 的切源/重建回滚副本，但均与主仓库位于同一生产磁盘。没有发现
qsys 专用 backup timer、用户 cron、restic/borg 服务、异地副本或恢复演练证据。
这些目录是操作回滚点，不是灾备。

目标策略：每日增量、每周完整、加密异地、7/30/180 天分层保留；每季度恢复到隔离
目录并验证文件 SHA256、Parquet footer、schema、行数和关键查询。备份目的地、加密
密钥托管和费用属于部署决策，本分支不擅自选择外部服务或写入生产。

本分支已提供不负责复制数据的验收工具，先为源仓库生成不可变 manifest，再对隔离
恢复目录逐文件验证大小、SHA256、Parquet 可读性、行数和 Arrow schema：

```bash
flock --exclusive var/warehouse-write.lock \
  uv run python scripts/verify_warehouse_backup.py create \
    --root /data/qsys/warehouse --manifest /data/qsys/audit/warehouse-manifest.json
uv run python scripts/verify_warehouse_backup.py verify \
  --root /mnt/isolated-restore --manifest /data/qsys/audit/warehouse-manifest.json
```

`create` 必须针对存储快照执行，或像上例一样全程持有仓库写锁；否则跨文件扫描不能
代表同一个时间点。`verify` 应在隔离恢复目录运行，额外文件同样判失败。

## 8. 部署约束

部署后 `A3.paid_minute_override_gross_vs_daily` 会因 5.3 的 24 个标的日阻断，这是
如实报告，不是部署故障。canonical 覆盖失败关闭可以先在测试环境验证，预期影响是
旧年份分钟回测从“空结果”改为明确失败。

四个生产定时写任务使用同一个 `var/warehouse-write.lock`，冲突时后启动者立即明确
失败，不允许两个读—合并—覆盖事务并发。底层 Parquet 落盘也改用进程唯一临时文件，
避免未经过 systemd 的写入者互相破坏 `.tmp`。手工写仓库时必须复用同一把锁；
canonical 回填命令已默认复用该锁。
