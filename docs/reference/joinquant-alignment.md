# 与聚宽逐笔对齐：口径清单

目标是**非特殊情况下 100% 对齐**。这份文档把「对不齐」拆成一条条可判定的
口径，每条注明：由谁来改、是否已消除、怎么验证。

对账区间：`2025-09-10 ~ 2026-09-08`（分钟线覆盖区间，241 个交易日）。

## 二、我这边已改（qsys）

### 1. 成交量上限的单位错误 —— 上限收紧了 100 倍

`bar.volume` 的单位是**手**，`order.qty` 的单位是**股**，
`SimBroker` 直接拿两者相比。实测 86.5 万根日线，**99.88%** 满足
`low <= amount/(volume*100) <= high`，按「股」解释 **0 条**命中。

小资金撞不到这个上限，用 159.6 万本金对账时一天冒出 155 次
`volume_capped` 才暴露。修复后拒单 158 -> 0。

**注意方向**：这个 bug 原本在**帮倒忙**（挡掉了部分大额亏损单），
修完收益 +87.29% -> **+73.11%**。

### 2. 成本口径 —— `--jq-compat`

原策略**没有调用** `set_slippage` / `set_order_cost`，用的是聚宽默认值。
不凭记忆，从它导出的 86 笔 lot 反推 `entry_price / open`：

```
count 86   mean 0.00117   median 0.001241   std 0.000407
```

中位数 **0.001241** 正是 `PriceRelatedSlippage(0.00246)` 的单边值
0.00123（离散来自两位小数取整）。

| | qsys 默认（实盘档位） | `--jq-compat`（聚宽默认） |
|---|---|---|
| 滑点 | 0.05% | **0.123%** |
| 印花税（卖出） | 0.05%（现行） | **0.1%**（聚宽仍用旧税率） |
| 过户费 | 0.001% 双向 | **0**（聚宽默认不收） |

**聚宽的成本更贵**：同配置下 +73.11% -> **+55.22%**，差 17.9 个百分点。
对账必须加 `--jq-compat`，日常决策用默认档位。

### 3. 持仓期分钟线缺失（已修，见 2-2c 计划文档）

分钟线只覆盖买入决策要的那几天，退出拿不到报价就静默跳过，持仓永久
卡死、抽干现金。修复后 -8.73% -> +71.85%。

## 三、拿到 `regime_daily` 之后：分歧定位到 ST 判定

聚宽第二版导出补上了 `regime_daily.csv`（792 天）。它带 `signal_date` 与
`source_market_date` 两列，直接坐实了 T-1 口径：**date=T 的行算的是
T-1 的行情**。join 键用 `source_market_date`（对 `limit_up_count` 的
精确命中 70 天，用 `date` 只有 16 天）。

### 逐因子比对：五个 Gate 判定里四个已在 99% 以上

| 因子判定 | 全区间 | 近窗口 |
|---|---|---|
| LOW_MAIN · `index_ma20_slope_5d` > -0.009053 | **100.0%** | **100.0%** |
| HIGH_CHINEXT · `market_advance_ratio` > 0.5105 | 99.9% | 99.6% |
| HIGH_MAIN · `market_median_return_1d` > 0.004255 | 99.9% | 99.6% |
| LOW_MAIN · `prior_limitup_nextday_return_mean` > 0.006959 | 97.6% | 99.2% |
| **HIGH_CHINEXT · `touched_limit_up_count` > 103.33** | **90.7%** | **83.3%** |

短板只有一个：`touched_limit_up_count`。近窗口 **40 天多放行、0 天多拒掉**
——单边偏差，正是多选的直接来源。

### 根因：ST 反推只用「当日命中」一条，误判率太高

我们没有历史 ST 名单（QMT 没有 ST 板块，`get_instrument_detail` 只给当日
涨跌停价；akshare 的东财接口在拒，新浪的曾用名接口不带日期），只能从
价格反推：`high` 恰好等于 `round(前收 x 1.05, 2)` 就按 5% 判。

问题是这个巧合很常见：一只 ¥10 的股当日高点落在 +5% 那一分上的概率约
1/10，全市场每天撞出十几个。实测我们每天造 24 个 ST 标记，真值约 17。

**修正**：加第二条——该股回看 60 根内被第一条命中过 **>= 2 次**。ST 是
持续数月的状态，真 ST 反复贴板，巧合只命中一次。只回看不前瞻。

拿 792 天真值标定（`docs` 外的一次性脚本，结论已写进 `flags.py` docstring）：

| 规则 | 触板数平均绝对误差 | Gate 全区间一致 | 近窗一致 | 近窗多放行 |
|---|---|---|---|---|
| 不判 ST | 19.1 | 83.3% | 77.9% | 0（多拒 53） |
| 只用第 1 条（原口径） | 11.2 | 90.7% | 83.3% | **40** |
| **加第 2 条（窗 60）** | **4.4** | **96.3%** | **93.8%** | **12** |

窗口取 40/60/90/120 的一致率是 96.1/96.3/96.7/96.7%，**都在噪声内**。

（早先曾用「回看 20 根涨幅未超 5%」做佐证并以 57 个样本否决。真值多了
14 倍后重测，那条确实不如「命中 >=2 次」：平均绝对误差 8.9 对 4.4。）

## 四、原策略改了执行：CASH-SAFE V2

聚宽第三版在买入侧加了执行保护，透支问题**在原策略里已经解决**：

```python
protect_price = min(day_open * 1.002, high_limit)
fee_reserve   = max(5.0, budget * 0.0003) + budget * 0.00001
safe_qty      = int((budget - fee_reserve) / protect_price / 100) * 100
order(stock, safe_qty, LimitOrderStyle(protect_price))
```

实测：`available_cash` 为负的天数 **44/241 -> 0/241**，82 笔成交中限价保护
被击穿 **0 次**，成交价仍是 `day_open x 1.00123`（滑点未变）。

我们跟着改了 `allocation.py`：同样的保护价、同样的费用准备金（准备金用
原文写死的常数，与实际成本模型无关——照抄才对得上定量），并改为挂限价单
而非市价单。回测里开盘价永远低于保护价，成交结果不变；**实盘才见效**。

改之前我们的定量与它 72/82 一致，改之后共同 79 笔里 **49 笔完全相同、
成交价 79/79 一致**。

| **重合** | — | **79 / 82 = 96.3%** |

| 共同 79 笔的单笔均值 | +3.25% | +3.25% |

**逐笔收益完全一致，成交价 79/79 一致。**

### 但收益仍差 24 个点：多选会把同日的仓位摊薄

共同 79 笔里**股数不一致 30 笔，我们总投入少 6.81%**：

```
2026-06-02  301236.SZ  聚宽 3,500 股(145,110)  我们 1,400 股(58,044)  当日现金 145,278
2026-07-06  002249.SZ  聚宽 13,400 股(113,364) 我们 6,700 股(56,682)  当日现金 113,673
```

那两天聚宽**只有一个候选、满仓打**，我们各多选了一只，同一笔钱摊成两半。
S8 在当日候选内部归一化——**多选一只，同日那笔好交易的仓位直接砍半**。
所以 5 笔多选的代价远不止它们自己的 -2.48%。

### 8 笔分歧的逐条归因

| 笔 | 类别 | 原因 |
|---|---|---|
| 2026-06-08 `603859.SH` | 漏买 | `market_median_return_1d` 0.0040714 vs 0.0044262，阈值 0.0042555 |
| 2026-05-06 `300885.SZ` | 漏买 | `market_advance_ratio` 0.507338 vs 0.5107431，阈值 0.5104943 |
| 2026-06-11 `603636.SH` | 漏买 | `prior_limitup_nextday_return_mean` 0.0072793 vs 0.0068665，阈值 0.0069592 |
| 2026-05-22 `000536.SZ` | 多买 | **聚宽自己也放行了**，只是它当天没钱 |
| 2026-06-25 `002550.SZ` | 多买 | 个股因子分歧：聚宽 RISK（`stock_return_10d` / `distance_to_60d_high`） |
| 2026-06-02 `002328.SZ` | 多买 | 入场比值 1.000953，离下界 1.00 只有 **+0.095%** |
| 2026-07-07 `301191.SZ` | 多买 | 入场比值 0.968965，离上界 0.970 只有 **0.103%** |
| 2026-07-06 `301379.SZ` | 多买 | 比值 1.0308 在区间中部，另有原因，未定位 |

三笔漏买**全部是阈值上的毫厘之差**，且都指向同一个源头：广度类因子的标的池。

### 广度因子差在哪：两个方向相反的偏差

标的池家数逐日比对（241 天，聚宽 `market_valid_stock_count` vs 我们的
`valid_stock_count`）：

| | 值 |
|---|---|
| 我们更少的天数 | **233 / 241** |
| 平均差 | **−14.6 只** |
| 中位 / 最差 | −16 / **−49**（2026-04-29） |
| 少 ≥ 20 只的天数 | 92 |

这个差**由两个方向相反的原因叠加**，必须拆开看，否则会把责任归错边。

**A. 我们少的：当时在册、几个月后退市的票。**
mootdx 完全不提供；QMT 返回的 bar **四价全是 0.0，分钟线也一样**
（实测 600421/600599/600608/600636/600696/605081 在 2026-06-08~10
`suspendFlag=0`、成交量真实——12.9 万 ~ 79 万手——但价格全被抹掉）。
akshare 两条接口也都取不到。**两个数据源都拿不到，这条不可修复。**

**B. 聚宽多的：当日停牌、却被算进当日截面的票。**
`_s5_market_raw_factors` 用 `groupby().cumcount(ascending=False)` 定 t1/t2，
**从不校验日期等于目标日**。停牌股当日行被 `paused == 0` 滤掉后，
`_rank_rev == 0` 落到前一交易日——**前一日的涨跌被挂到了目标日**。
详见下面两个已结案的日期。

### 已结案：2026-05-06 `market_advance_ratio` —— 聚宽的 stale-bar bug

| | advance_ratio | 阈值 0.5104943 |
|---|---|---|
| **qsys 0.5100474** | 剔除停牌股 | 阈值之下 → OTHER |
| 聚宽 0.5107431 | 含 41 笔陈旧收益 | 阈值之上 → FAVORABLE |

2026-04-30 聚宽比我们多 41 只，其中 **32 只当日停牌**（QMT `suspend_flag=1`、
volume 0、四价等于前收），另 9 只是上面的 A 类。对 32 只全部核对：
聚宽的 `close_t1` == 04-29 收盘、`close_t2` == 04-28 收盘，**32/32 命中**。

同期我们做了全区间日线空洞普查（`find_holes`）：5,008 个内部空洞 / 818 只，
高峰全在年报截止日；从 QMT 逐只补采 72.7 万行后 `filled=0, suspended=4,974`
——**空洞全是真停牌，不是采集缺口**。

**结论：这天 qsys 对、聚宽错。** 300885.SZ 那笔多选、以及后续
600863 → 000536 的连锁账户分叉，都归到这一个根因下，不再单列。

### 已结案：2026-06-11 `prior_limitup_nextday_return_mean` —— 反过来是 A 类

信号日 2026-06-11，`source_market_date` = 2026-06-10，
聚宽窗口 `count=3` = [06-08, 06-09, 06-10]，应有 t1=06-10 / t2=06-09。

在**同一份 qsys 数据**上同时跑两套口径：

| 口径 | universe | sample_count | mean | median |
|---|---|---|---|---|
| OLD_JQ_STYLE（按 `_rank_rev` 取，日期不校验） | 4,582 | 128 | 0.0072792980 | 0.0014010402 |
| STRICT_DATE_STYLE（t1/t2 必须等于目标日） | 4,580 | 128 | 0.0072792980 | 0.0014010402 |
| 聚宽导出 | 4,592 | ? | **0.0068664687** | 0.0014010402 |

`JQ_ONLY 0 / QSYS_ONLY 0 / BOTH 128 / BOTH_RET_DIFF 0`。
窗口内日期错位的只有 2 只（003032.SZ、300225.SZ，都是 06-10 停牌），
**两只都不在样本内**。

**所以这一天的差与 stale-bar 无关，严格日期对齐一个字都不会改。**
差的是标的池：4,592 − 4,585 = 7，加上 2 只 06-10 停牌股正好是 t1 口径的
4,592 − 4,581 = 11。QMT 已证实其中 6 只 A 类退市股在 06-08~10 真实成交。

两边**中位数完全相等（10 位小数）**，说明样本是「成对进出」而非单只错位；
均值缺口 −0.0004128 对应的算术约束：

| 聚宽多几只 | 这几只收益和须为 | 均值 |
|---|---|---|
| 2 | −0.039109 | −1.96% |
| 3 | −0.032243 | −1.07% |
| **4** | **−0.025376** | **−0.63%** |

我们 06-09 数出 128 个涨停、聚宽 132 个，差正好 4。退市整理期个股当日涨停、
次日回落属常态，与这组数字自洽。**这一天是我们缺数据，不是聚宽算错。**

逐股明细：`var/prior_limitup_20260610_{old_style,strict,sample128}.csv`，
列为 `stock, t1_time, t2_time, close_t1, close_t2, high_limit_t2,
paused_t1, paused_t2, was_limit_up_t2, ret_t1, is_prior_limitup_sample,
stale_t1, stale_t2`。

## 六、剩余的真差异

| 项 | 现状 | 能否消除 |
|---|---|---|

| 个股因子分歧 | `stock_return_10d` / `distance_to_60d_high` 1 笔 | 待查 |
| `301379.SZ` 多选 | 入场比值在区间中部，另有原因 | 待查 |
| lot 级账本 | 退出按持仓均价，非每笔入场价 | 需实现 |

### 「特殊情况」是两条，都是数据可得性

1. **退市股**：两个数据源都不提供，广度因子必然有 0.04% 量级的偏差。
   落在阈值上才翻——实测 241 天里各翻 1 天（2026-06-11 就是这一天）。
   注意这条与聚宽的 stale-bar bug **方向相反**，某些日子会互相抵消，
   不能因为总差很小就认为两边都对。
2. **竞价快照**：QMT tick 只有约 20 个交易日（实测边界 2026-08-10 /
   锚点 2026-09-08）。过去一年取不回来，只能从今天起每日归档、向前验证。
   每日归档已上线：137 只 / 17,224 笔 / 24 秒，竞价末价与日线开盘价
   **55/55 一致**。

其余每一条都还有路可走。
