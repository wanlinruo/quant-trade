# 与聚宽逐笔对齐：口径清单

目标是**非特殊情况下 100% 对齐**。这份文档把「对不齐」拆成一条条可判定的
口径，每条注明：由谁来改、是否已消除、怎么验证。

对账区间：`2025-09-10 ~ 2026-09-08`（分钟线覆盖区间，241 个交易日）。

## 二、我这边已改（qsys）

### 1. 成交量上限的单位错误 —— 上限收紧了 100 倍

`bar.volume` 的单位是**手**，`order.qty` 的单位是**股**，
`SimBroker` 直接拿两者相比。实测 86.5 万根日线，**99.88%** 满足
`low <= amount/(volume*100) <= high`，按「股」解释 **0 条**命中。

小资金撞不到这个上限，用 159.6 万本金对账时一天冒出 155 次
`volume_capped` 才暴露。修复后拒单 158 -> 0。

**注意方向**：这个 bug 原本在**帮倒忙**（挡掉了部分大额亏损单），
修完收益 +87.29% -> **+73.11%**。

### 2. 成本口径 —— `--jq-compat`

原策略**没有调用** `set_slippage` / `set_order_cost`，用的是聚宽默认值。
不凭记忆，从它导出的 86 笔 lot 反推 `entry_price / open`：

```
count 86   mean 0.00117   median 0.001241   std 0.000407
```

中位数 **0.001241** 正是 `PriceRelatedSlippage(0.00246)` 的单边值
0.00123（离散来自两位小数取整）。

| | qsys 默认（实盘档位） | `--jq-compat`（聚宽默认） |
|---|---|---|
| 滑点 | 0.05% | **0.123%** |
| 印花税（卖出） | 0.05%（现行） | **0.1%**（聚宽仍用旧税率） |
| 过户费 | 0.001% 双向 | **0**（聚宽默认不收） |

**聚宽的成本更贵**：同配置下 +73.11% -> **+55.22%**，差 17.9 个百分点。
对账必须加 `--jq-compat`，日常决策用默认档位。

### 3. 持仓期分钟线缺失（已修，见 2-2c 计划文档）

分钟线只覆盖买入决策要的那几天，退出拿不到报价就静默跳过，持仓永久
卡死、抽干现金。修复后 -8.73% -> +71.85%。

## 三、同起点重跑之后：分歧收敛到**一条规则**

先澄清一件事：**聚宽在窗口起点是 0 持仓、100% 现金**（2025-09-10
`total_value = available_cash = 1,595,648`，`position_count = 0`），没有
跨窗口的仓位。所以用 `--cash 1595648 --jq-compat` 重跑，就是**同起点、
同持仓状态、同成本**的对齐比较，不需要你在聚宽那边重跑区间。

### 结果矩阵

| 本金 | 成本口径 | 总收益 | 买入 | 与聚宽重合 |
|---|---|---|---|---|
| 100,000 | qsys 实盘档位 | +67.31% | 83 | — |
| 100,000 | 聚宽默认 | +48.95% | 83 | — |
| 1,595,648 | qsys 实盘档位 | +73.11% | 89 | — |
| **1,595,648** | **聚宽默认** | **+55.22%** | **86** | **74 / 86** |
| 聚宽实测 | 聚宽默认 | +109.93% | 86 | — |

同起点同成本下**买入笔数完全相同（86 vs 86）**，重合 74 笔。

### 分歧的根：第一次分叉在 2025-11-25

从 2025-09-10 起的**头两个半月，两边买入集合逐日完全相同**。第一次分叉：

```
2025-11-25   聚宽 [600629.SH]
             我们 [300516.SZ, 600629.SH]
```

之后的差异全是下游级联——满仓策略里多买一只就改变次日现金，
现金又改变次日买得起什么，一步分叉整条路径分家。

### 分叉的原因：HIGH_CHINEXT 的 S7 Gate 输入因子

三笔多选（2025-11-25 `300516.SZ`、2026-03-19 `300302.SZ` 与 `301306.SZ`）
**签名完全一致**：

| | 聚宽 | qsys |
|---|---|---|
| `s7_state` | `OTHER` | `FAVORABLE` |
| `reason` | `ACTIVITY_OR_BREADTH_LOW` | `ACTIVITY_AND_BREADTH_OK` |
| `real_allow` | False | True |

Gate 逻辑本身是**逐字忠实移植**（原文 L1974-L1988 对 `gate.py`
L123-L134，同阈值、同 `three_and`、同 reason 串），所以分歧只能在
**输入因子**：`touched_limit_up_count` 与 `market_advance_ratio`。

我们的实测值：

```
阈值   touched > 103.33333333333333   advance > 0.5104943476458254
2026-03-19（读 T-1 03-18）  touched=104   advance=0.651873
2025-11-25（读 T-1 11-24）  touched=117   advance=0.780948
```

- **2026-03-19 是 104 vs 103.33——差一只票就翻。** 我们的涨停判定
  对聚宽是 52/57（ST 从价格反推），多数一只完全可能。
- **2025-11-25 差距大**（117 与 0.78 都远在阈值上方），聚宽却判 OTHER。
  这条**光靠我这边的数据定位不了**。

另外三笔「多买」（`000008.SZ` 2026-01-07、`600916.SH` 2026-01-26、
`600682.SH` 2026-03-27）**不是判定分歧**——聚宽的 `gate_decisions.csv`
对它们都是 `real_allow=True`，只是它当天没买（资金）。

## 需要你在聚宽那边做的**唯一一件事**

原文 `record_market_regime`（L2424）把每日环境因子存在
`g.regime_daily[day]` 里，但**没有导出**。请在导出代码里加一份：

```python
import pandas as pd
pd.DataFrame([
    {'date': d, **(v or {})} for d, v in sorted(g.regime_daily.items())
]).to_csv('regime_daily.csv', index=False)
```

有了它我就能**逐日逐因子**比对 `touched_limit_up_count`、
`market_advance_ratio`、`index_ma20_slope_5d`、
`prior_limitup_nextday_return_mean`，把分歧定位到具体是哪个因子、
差多少——而不是靠猜。这是把重合率推到 100% 的最后一把钥匙。

区间与本金**不用改**——聚宽窗口起点已是 0 持仓，我这边用
`--cash 1595648 --jq-compat` 就能对齐。

## 四、剩余的真差异（拿到同口径数据后逐条清）

| 项 | 现状 | 能否消除 |
|---|---|---|
| **HIGH_CHINEXT 因子** | 3 笔多选，同一签名（见上） | 需要聚宽的 `regime_daily` 才能定位 |
| 其余 Gate 状态分歧 | 近窗口 8/236，另 2 笔漏选待查 | 应可消除 |
| **竞价价口径** | 原文 `get_call_auction` 第 1 条的 `current`；我们用 `day_open` | ✅ tick 已能取到，但**只回溯 20 个交易日** |
| **竞价量口径** | 原文同一条记录的 `volume`；我们用 09:30 分钟 bar | 同上 |
| ST 判定 | 我们从价格反推（`high == prev_close × 1.05`），命中 52/57 | 需要真实 ST 名单才能消除 |
| lot 级账本 | 退出按持仓均价，非每笔入场价 | 需实现 lot 账本 |

### 「特殊情况」只有一条

**竞价价/量口径**：QMT 的 tick 只回溯约 20 个交易日（实测边界
2026-08-10 / 锚点 2026-09-08），过去一年的竞价快照**取不回来**。
所以这条在历史区间上无法对齐，只能从今天起每日归档、向前验证。
每日归档已接入 `daily_archive.py`。

其余每一条都应当能清到零。
