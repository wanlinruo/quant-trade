# 与聚宽逐笔对齐：口径清单

目标是**非特殊情况下 100% 对齐**。这份文档把「对不齐」拆成一条条可判定的
口径，每条注明：由谁来改、是否已消除、怎么验证。

对账区间：`2025-09-10 ~ 2026-09-08`（分钟线覆盖区间，241 个交易日）。

---

## 二、我这边已改（qsys）

### 1. 成交量上限的单位错误 —— 上限收紧了 100 倍

`bar.volume` 的单位是**手**，`order.qty` 的单位是**股**，
`SimBroker` 直接拿两者相比。实测 86.5 万根日线，**99.88%** 满足
`low <= amount/(volume*100) <= high`，按「股」解释 **0 条**命中。

小资金撞不到这个上限，用 159.6 万本金对账时一天冒出 155 次
`volume_capped` 才暴露。修复后拒单 158 -> 0。

**注意方向**：这个 bug 原本在**帮倒忙**（挡掉了部分大额亏损单），
修完收益 +87.29% -> **+73.11%**。

### 2. 成本口径 —— `--jq-compat`

原策略**没有调用** `set_slippage` / `set_order_cost`，用的是聚宽默认值。
不凭记忆，从它导出的 86 笔 lot 反推 `entry_price / open`：

```
count 86   mean 0.00117   median 0.001241   std 0.000407
```

中位数 **0.001241** 正是 `PriceRelatedSlippage(0.00246)` 的单边值
0.00123（离散来自两位小数取整）。

| | qsys 默认（实盘档位） | `--jq-compat`（聚宽默认） |
|---|---|---|
| 滑点 | 0.05% | **0.123%** |
| 印花税（卖出） | 0.05%（现行） | **0.1%**（聚宽仍用旧税率） |
| 过户费 | 0.001% 双向 | **0**（聚宽默认不收） |

**聚宽的成本更贵**：同配置下 +73.11% -> **+55.22%**，差 17.9 个百分点。
对账必须加 `--jq-compat`，日常决策用默认档位。

### 3. 持仓期分钟线缺失（已修，见 2-2c 计划文档）

分钟线只覆盖买入决策要的那几天，退出拿不到报价就静默跳过，持仓永久
卡死、抽干现金。修复后 -8.73% -> +71.85%。

## 三、需要你在聚宽那边改 —— **这是目前最大的一条**

### 资金路径依赖：把区间和本金对齐

聚宽的净值是 **2023-06-06 用 10 万起跑**，到 2025-09-10 已滚到
**1,595,648**。我们的精确版窗口只有 241 天。两边在同一天的可用现金
完全不同步，而这个策略是**满仓建仓**——买不买得起直接改变持仓，
持仓又改变次日的现金，一步错就整条路径分叉。

证据：聚宽 2026-07-31 买的那 6 只，每笔 `entry_notional` 只有
**约 1.4 万**，占它当时 262 万账户的 **3%**——它当天现金也见底了。
我们账上 918 元，按 7 只分摊每只 131 元，买不起一手，全部
`BELOW_BOARD_LOT`。**同一套逻辑，不同的钱。**

**请在聚宽上重跑一次，只改两处，其余一律不动：**

```python
# 回测区间
起始日期 = 2025-09-10
结束日期 = 2026-09-08

# 初始资金
initial_cash = 100000
```

- **不要**加 `set_slippage` / `set_order_cost` —— 用默认值，我这边已对齐
- **不要**改任何阈值或分支逻辑 —— 保持 FROZEN FINAL
- 导出同一套文件：`gate_decisions.csv`、`daily_buy_details.csv`、
  `closed_lots.csv`、`daily_nav.csv`

拿到之后我用 `--cash 100000 --jq-compat` 重跑，两边同起点同成本，
剩下的任何差异都是真差异。

## 四、剩余的真差异（拿到同口径数据后逐条清）

| 项 | 现状 | 能否消除 |
|---|---|---|
| Gate 判定分歧 | 近窗口 8/236 状态不一致；多选 10、漏选 3 | 待逐条查，应可消除 |
| **竞价价口径** | 原文 `get_call_auction` 第 1 条的 `current`；我们用 `day_open` | ✅ tick 已能取到，但**只回溯 20 个交易日** |
| **竞价量口径** | 原文同一条记录的 `volume`；我们用 09:30 分钟 bar | 同上 |
| ST 判定 | 我们从价格反推（`high == prev_close × 1.05`），命中 52/57 | 需要真实 ST 名单才能消除 |
| lot 级账本 | 退出按持仓均价，非每笔入场价 | 需实现 lot 账本 |

### 「特殊情况」只有一条

**竞价价/量口径**：QMT 的 tick 只回溯约 20 个交易日（实测边界
2026-08-10 / 锚点 2026-09-08），过去一年的竞价快照**取不回来**。
所以这条在历史区间上无法对齐，只能从今天起每日归档、向前验证。
每日归档已接入 `daily_archive.py`。

其余每一条都应当能清到零。
