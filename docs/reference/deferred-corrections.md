**这份文档存在的理由**：换源过程中查出了一批「数据确实不对，但现在不能改」的事实。
不能改的原因只有一个——**数据源还没换完**。在 `paid_daily` 与 `tushare_daily`

**不是**「可以不做」。

**统一触发条件**：计划 A Task 10 与计划 C Task 10 都完成、生产查询层已切到最终真值源之后，
按本表顺序一次性处理。

## D-1 复权因子在非股改期存在大偏差

**事实**（`artifacts/task9-factor-verification-2026-09-13.md`，全市场 1990-12-19 至 2026-09-11）：

比较两种单日因子 `direct = factor(t)/factor(t-1)` 与 `computed = close(t-1)/pre_close(t)`：

| 阈值 | 差异股-日 |
|---|---:|
| `rel_diff > 0.1%` | 1,917 |
| `rel_diff > 1%` | 1,807（1,541 只标的，最大 871.73%）|

`>1%` 中 1,119 条落在 2005–2006 股改期（可解释），**但 688 条落在区间之外**。

抽查 `001331.SZ` 2026-06-30：`close=56.38 / pre_close=51.25`，价格反推因子为 1，
直取 `factor` 由 2.4011 跳到 3.4848（≈1.4513）。源字段自身不自洽。

**影响**：`adj_factors.cum_factor` 已按裁决改为直取 `factor`（Task 9），
所以当前生产值取的是源的真值。若源确有错，则前复权价错，进而影响所有依赖复权价的回测。

**为何现在不做**：归因需要独立行情源抽样验真。`paid_daily` 与 `tushare_daily`
同源（实测 18,224,238 行零差异），拿 Tushare 去验 Tushare 无意义。
需要第三方（同花顺/东财）逐条比对，属于独立调查，不属于换源工程。

**做的时候要做什么**：
1. 按三类分别解释——920 号段北交所（见 D-2）、2005–2006 股改期、非股改期 A 股；
2. 非股改期的 688 条逐条用独立数据源抽样验真；
3. 确认是源错的，向数据源方反馈并在 `adj_factors` 里记质检标记，**不得静默过滤**。

**证据**：`artifacts/factor_verification.parquet`、`artifacts/task9-factor-verification-2026-09-13.md`

## D-3 广度因子的历史口径含北交所

**事实**：`_in_breadth_universe` 用 `EXCLUDED_CODE_PREFIXES = ("4","8","68")` 排除北交所，
**但排不掉 `920xxx`**（北交所 2023 年启用的新号段，首字符是 `9`）。
生产实测 2026-09-09：北交所总数 343 只，**其中 920 号段 343 只，43/83/87 号段 0 只**。

也就是说这个过滤**从未生效过**，全部历史广度因子都是含北交所算出来的。

**影响**：这正是冻结的 S6/S7 阈值所拟合的那个股票池。Task 8 加上 `board_of`
板块过滤后，广度因子的分母变了，旧阈值不再对应同一个分布。

**为何现在不做**：这条本身已经修好（Task 8），留在此表是因为它**是 D-4 的成因**。

**证据**：`docs/reference/strategy-data-dependencies.md` §五

## D-4 S6/S7 阈值重标定

**事实**：`src/qsys/strategy/structural/params.py` 里的四个冻结阈值

```python
S6_LOW_TREND_WEAK_THRESHOLD = -0.009053065956339234
S6_LOW_HEAT_LOW_THRESHOLD   =  0.0069591652776029595
S6_HIGH_MAIN_BREADTH_HIGH   =  0.0042554739215828
S6_HC_ADVANCE_NOT_LOW       =  0.5104943476458254
```

由 `src/qsys/strategy/structural/gate.py` 消费，来源是上一轮 2025 TRAIN 的分位数/消融过程。
它们拟合的是**含北交所、ST 靠价格反推、复权因子自算**的那份数据。
换源后这三项全变了（D-3、Task 7、Task 9），阈值失去了它所对应的分布。

**影响**：直接拿旧阈值跑新数据，Gate 的开合频率会漂移，且漂移量无法解释。

**为何现在不做**：**重标定必须只做一次**。计划 C 的 `stk_limit` 与 `limit_list_d`
还会再改首板/炸板判定，那是 S7 的直接输入。在计划 C 之前重标，做完就作废。

**做的时候要做什么**：这是**研究任务，不是数据层任务**。要重跑原来那套分位/消融流程，
不能把它折进计划 A/C 的任一任务里——折进去就毁掉了三段式归因
（spec §10：第 1 段只换源、第 2 段加 ST 真值、第 3 段加因子直取，逐段隔离才能把
回测差异归到具体原因上）。

## D-5 `_in_breadth_universe` 与 `board_of` 两层过滤口径不一致

**事实**：`market_regime` 先用原策略的 `4/8/68` 前缀表过滤，再按调用方的 `boards` 取交集。
前一层不排 B 股（900/200），后一层生产默认 `main,gem,star` 会排除 `bshare`，两层语义不一致。

**影响**：当前为零。实测 2026-09-09 付费源全市场 5,550 只、旧表 `bars_daily` 同日，
900/200 开头均为 **0 只**。

**为何现在不做**：合并两层等于改广度股票池的定义。在没有任何 B 股数据的情况下做这个决定，
是拿偶然的交集替代口径决策。

**做的时候要做什么**：先明确广度池是否纳入外币计价标的，再统一过滤口径，
然后重新评估 S6/S7 阈值（并入 D-4 一起做）。

**证据**：`docs/reference/strategy-data-dependencies.md` §五

## D-6 `tushare_daily.name` 恒为 null 会让候选池静默归零

**事实**：计划 C 的 `compose_daily` 把 `name` 留给 `namechange` 单独成表
（`src/qsys/data/pipeline/tushare_daily.py:99-100`），因此 `tushare_daily.name` 恒为 null。

链路：

```
name = null → is_st = null → limit_pct = null → limit_up = null
  → (close >= limit_up) = null → .fill_null(False)（flags.py:203-205）
  → is_limit_up 全市场 False → is_first_board 全市场 False
  → 候选池永远为空，且不报错
```

**影响**：当前不触发（`build_daily_flags` 读的是 `query.paid_daily`，那张表有 `name`）。
但计划 C Task 10 若把派生链路切到 `tushare_daily`，就会全线静默失效。

**为何现在不做**：它是**计划 C Task 10 的硬阻断条件**，不是独立待办。

**做的时候要做什么**：计划 C Task 10 之前必须先完成计划 C Task 7
（`namechange` → name/ST 真值）并把 `name` 接进派生链路；
且 `build_daily_flags` 要加一道闸门——`name` 大面积为 null 时**显式报错**，
而不是静默产出空候选池。与 `daily_archive` 的 `source_is_serving` 探针同一思路。

## D-7 竞价逐笔数据只有 8 天

**事实**：`auction_ticks` 仅有 2026-09-03 至 09-10 共 8 天、265 只标的。
Tushare 的 `stk_auction` 是 9:25 撮合完成后的结果数据，与策略需要的
09:15–09:24 逐笔快照不是同一口径，用它替代会引入前视偏差。

**影响**：策略的三个入场判定（`check_low_open` / `check_high_open` /
`check_weak_to_strong`）与 09:24 早单路径全部依赖竞价逐笔。8 天不足以做任何绩效结论。

**为何现在不做**：这不是能「补」的东西——**漏一天永久缺一天**，只能靠每天采集积累。

**做的时候要做什么**：保证 QMT 采集链路每个交易日都跑通，并把
`auction_ticks` 的每日到货纳入质检告警。这条**不等换源，立即生效**。

**证据**：`docs/reference/strategy-data-dependencies.md` §三、§四
