## D-1 复权因子在非股改期存在大偏差

**事实**（`artifacts/task9-factor-verification-2026-09-13.md`，全市场 1990-12-19 至 2026-09-11）：

比较两种单日因子 `direct = factor(t)/factor(t-1)` 与 `computed = close(t-1)/pre_close(t)`：

| 阈值 | 差异股-日 |
|---|---:|
| `rel_diff > 0.1%` | 1,917 |
| `rel_diff > 1%` | 1,807（1,541 只标的，最大 871.73%）|

`>1%` 中 1,119 条落在 2005–2006 股改期。原记录把区间外 688 条都归入 D-1；
2026-10-06 独立验真确认其中 369 条属于 D-2 北交所上市身份边界，真正的非股改期
D-1 为 **319 条、229 只证券**。

抽查 `001331.SZ` 2026-06-30：`close=56.38 / pre_close=51.25`，价格反推因子为 1，
直取 `factor` 由 2.4011 跳到 3.4848（≈1.4513）。源字段自身不自洽。

**影响**：`adj_factors.cum_factor` 已按裁决改为直取 `factor`（Task 9），
所以当前生产值取的是源的真值。若源确有错，则前复权价错，进而影响所有依赖复权价的回测。

**为何现在不做**：归因需要独立行情源抽样验真。`paid_daily` 与 `tushare_daily`
同源（实测 18,224,238 行零差异），拿 Tushare 去验 Tushare 无意义。
需要第三方（同花顺/东财）逐条比对，属于独立调查，不属于换源工程。

### 2026-09-14 补充：换源回归第 3 段给出了成因分类

Task 10 第 3 段对 `rel > 1%` 的 59 只标的做了逐只分类。**判据只用付费源自身的
两列**——当日 `pre_close` 相对上一根实际 bar 的 `close` 偏离（价格缺口），
与直取 `factor` 相对上一根 bar 的跳变。价格是仲裁者；`corporate_actions`
不参与判定，只作旁证——它是第三方 akshare 数据，拿一个未经验证的源去裁决
另一个源没有意义。

| 判定 | 理由 | 只数 |
|---|---|---:|
| 新值自洽 | 因子跳变精确匹配价格缺口 `gap/(1-gap)` | 35 |
| 新值自洽 | 价格无缺口、因子不跳；旧值却调整了 | 4 |
| **新值不自洽** | **价格有真实除权缺口，但直取因子不跳** | **12** |
| 新值不自洽 | 因子跳变与价格缺口幅度不符 | 5 |
| 新值不自洽 | 价格无缺口，但直取因子跳了 | 3 |

合计 39 自洽 / 20 不自洽 / 0 未定。

**这套判据只能判自洽，不能判客观真值。** 它回答的是「两个候选因子里哪个与
付费源自己的价格序列自洽」。要定客观真值必须引入独立行情源——那正是本条待办
（D-1）本身要做的事。

**「价格有缺口但因子不跳」那 12 只是这次新查出来的源缺陷**，也是 D-1 里
「源字段不自洽」的具体形态。做过反驳性检验：若付费源只是把因子记到 T+1，
缺口应当一天后闭合；实测 12 只里 10 只的偏差一路持续到窗口末日，从未闭合，
T+1 假说被否。12 只：`000430.SZ`、`000691.SZ`、`000793.SZ`、`000908.SZ`、

**可自动检测**：`|pre_close(t) - close(t-1)| / close(t-1)` 明显非零，
而 `factor(t) / factor(t-1)` 为 1，即为疑似漏除权。这条应该做成质检规则，

## D-6 `tushare_daily.name` 恒为 null 会让候选池静默归零

**状态：已于 2026-09-14 结案。** `namechange` 已完整分页落入 `name_history`，
`build_daily_flags` 用区间 as-of 连接取得当日名称，并在 100 行以上的窗口中对

4,568,042 行中 4,474,268 行有名称结论（97.95%），未覆盖行保持 null。

**事实**：计划 C 的 `compose_daily` 把 `name` 留给 `namechange` 单独成表
（`src/qsys/data/pipeline/tushare_daily.py:99-100`），因此 `tushare_daily.name` 恒为 null。

链路：

```
name = null → is_st = null → limit_pct = null → limit_up = null
  → (close >= limit_up) = null → .fill_null(False)（flags.py:203-205）
  → is_limit_up 全市场 False → is_first_board 全市场 False
  → 候选池永远为空，且不报错
```

**原影响**：切换前不触发；若直接换到 `tushare_daily` 会全线静默失效。

**处理时点**：作为计划 C Task 10 的硬阻断条件随换源一并完成。

**做的时候要做什么**：计划 C Task 10 之前必须先完成计划 C Task 7
（`namechange` → name/ST 真值）并把 `name` 接进派生链路；
且 `build_daily_flags` 要加一道闸门——`name` 大面积为 null 时**显式报错**，
而不是静默产出空候选池。与 `daily_archive` 的 `source_is_serving` 探针同一思路。

## D-9 `feed.py` 的 `fill_null(1.0)` 在新因子语义下是任意值（已了结）

**事实**：`src/qsys/data/feed.py:85` 有 `pl.col("cum_factor").fill_null(1.0)`。

旧语义下 `cum_factor` 以窗口首日归一，1.0 就是首日值，填进去与序列同量级。
新语义下 `factor` 是付费源自带锚点的累计值，同一窗口内可以是 2.40–3.48
（D-1 抽查的 `001331.SZ`），全历史跨度更大。**填 1.0 等于把该行价格打到几分之一。**

**影响**：这是价格链路上一处字面意义的**填充**，与「拿不到的数据记 null，
不准填」的硬约束正面冲突。Task 9 改了因子语义却没有回头看这处常量。

**为何现在不做**：改成 null 传播会让缺因子的行整行价格变 null，下游消费方
（撮合、选股）当前是否都能处理 null 价格未经核实。贸然改可能把静默错误
换成运行时崩溃——两者都不可接受，需要先盘清消费方。

**做的时候要做什么**：
1. 盘清 `feed.py` 的全部消费方对 null 价格的处理；
2. 把 `fill_null(1.0)` 改为要么 null 传播、要么显式报错，**不保留静默默认值**；
3. 加测试守住：因子缺失的行不得产出一个看起来正常的价格。

### 2026-09-15 处置

消费方已盘清：生产中只有 `StructuralSelection._history()` 请求
`Adjustment.FORWARD`；回测引擎、动态 MA5 与普通 `Context` 均使用默认的
`Adjustment.NONE`，`BACKWARD` 只在测试里显式调用。

修复实际覆盖三处明面默认值，不是最初记录的一处：`cum_factor.fill_null(1.0)`、
`cum_share_factor.fill_null(1.0)`，以及旧 schema 缺 `cum_share_factor` 时的
`pl.lit(1.0)`。三者均改为 null 传播；同时移除了“因子查询结果整表为空就直接
返回原始价格”的隐式兜底。缺因子的股-日仍保留原键，但复权 OHLC 与成交量为
null，不再生成看似正常的错价。

唯一生产复权消费方 `StructuralSelection` 会在任何必需历史列含 null 时整只
跳过，并记录 `selection.history_incomplete` 及各列空值数；不在数值比较处崩溃，
也不通过 `drop_nulls` 悄悄缩短回看窗口。`C1.no_fill` 已把数据与策略源码的
未登记填充做成常驻扫描，`feed.py` 的回归测试同时覆盖“别的标的有因子”和
“因子表整张为空”两种缺失形态。

## D-10 `namechange` 区间的空洞让 867 个首板静默消失（已了结）

**事实**（`artifacts/第4段回归_付费源到Tushare换源_2026-09-14.md`）：

计划 C Task 10 把 `build_daily_flags` 从 `paid_daily` 切到 `tushare_daily` 后，
逐键对账显示这次换源是**纯净损失、零收益**：

| 字段 | 差异股-日 | 方向 |
|---|---:|---|
| `prev_close` / `adj_prev_close` | **0** | 价格完全一致 |
| `is_st` | 93,774（114 只）| 全部 `false` → **`null`** |
| `is_first_board` | 867（107 只）| 全部 `true` → **`false`** |

**根因**：`is_st` 由 `namechange` 的名称区间派生，而 `namechange` 只记录**变更事件**、

没有进 `namechange`，于是大量标的的最后一个区间停在 **2006-10-08**、
`end_date` 非 null 且无后继，此后全部无区间覆盖。
`000006.SZ` 因此在 2023-01-03 ~ 2026-09-11 整整 896 个交易日名称为 null。
另一种形态是区间中段空洞（`000023.SZ` 缺 2023-01-03 ~ 2023-04-28）。

**影响**：走的正是 D-6 那条静默失效链，只是幅度从「全市场」缩到 2.05%。
`_assert_name_coverage`（`flags.py:90`，调用点 `flags.py:160`）的 10% 闸门
按设计工作，但这次退化落在阈值之下，所以是静默的。
缺失集中在老上市标的上，有系统性偏差。

**为何现在不做**：修法涉及真值源架构决策（历史名称该取自哪个源），
需要拍板，不是实现细节。

**做的时候要做什么**——按「只许直取或纯派生」，可选的只有直取：

1. **推荐**：历史名称取 `paid_daily.name`（逐日、本区间 100% 覆盖、直取字段、
   历史静态不依赖手动转存的时效性），增量名称取 `namechange`。两个直取源各管一段。
2. 用 `stock_basic.name` 向后补尾部空洞——**含推断**（「此后没改过名」是假设
   不是事实），与规矩冲突，不可取。
3. 接受 2.05% 缺口——与「数据正确性优先」的原则冲突。

同时应把 `_assert_name_coverage` 的阈值重新审视：10% 挡得住全面失效，
挡不住这种 2% 量级的系统性缺口。考虑改为**按标的**判覆盖率，
而不是按全窗口行数。


### 2026-09-14 处置：历史已修复，增量路径仍有 96 只

用户拍板方案一，已实施（提交 `70f9b71`）。名称改按三个直取源排优先级解析
（`flags.resolve_names`）：`tushare_daily.name` → `paid_daily.name`（逐日观测）
→ `namechange` 区间。付费源按 `(symbol, dt)` 精确连接，不向前后蔓延。

复验结果：换源前后 `daily_flags` **逐键一致**——`is_st` / `limit_pct` /
`is_limit_up` / `is_first_board` 差异全部归零，首板总数还原到 50,525，
`is_st` 无 null，生产 `st_source` 全部为 `paid_daily`。

**残留待办**：`paid_daily` 覆盖到 2026-09-11 为止，此后的交易日只有
`namechange` 一个源，2006 断层还在——实测单日 **96 只标的无名称（1.73%）**。

可行修法需要先拍板：`instruments` 由每日同步刷新，其 `name` 是**同步当日**
的直接观测，用它填**当日**那一行是直取；但表里没有 `as_of` 列
（symbol/name/market/list_date/delist_date/board），无法从表内判断快照日期，
因而无法安全限定「只用于快照日」。**要走这条路必须先给 `instruments` 加
`as_of`**，否则拿它填历史就是结转。

另一条路是继续保留 `paid_daily` 的手动同步，仅为名称一列。代价是把已经

### 2026-09-14 了结：增量路径也补上了

用户拍板走「给 `instruments` 加 `as_of`」这条路。已实施（提交 `ef8cfb1`）。

**关键区分**：`stock_basic` 给的是当前名称——用它填历史是结转，
用它填**取快照那一天**是直接观测。区别只在于能不能确定快照是哪天取的。

但只加 `as_of` 不够：`instruments` 是覆盖写的单张表只留最新一份，而
`daily_flags` 每次同步要重建近 150 天。所以另建 `name_snapshots` 分区表，
按观测日逐日累积（`dt` = 取 `stock_basic` 的那一天）。这是**点观测**，
**不转成区间**——转区间要推断端点。

`resolve_names` 的优先级变为四级，全部是直取字段：

| 优先级 | 源 | 性质 | 覆盖 |
|---|---|---|---|
| 1 | `tushare_daily.name` | 当日字段 | 生产恒 null |
| 2 | `paid_daily.name` | 逐日观测 | 1990 ~ 2026-09-11 |
| 3 | `name_snapshots.name` | 逐日观测 | 2026-09-14 起累积 |
| 4 | `namechange` 区间 | 公告事件 | 有 2006 断层 |

两个逐日观测源都按 `(symbol, dt)` **精确连接**，只对它实际有行的那一天生效。

`as_of` 取**墙上时钟的今天**而不是正在同步的交易日：`stock_basic` 返回当前名称，
只对取数当天成立。补跑旧交易日时 `as_of` 仍是今天、与那个交易日对不上、
自然不生效——这正是想要的。同理 `build_instruments` 也显式收 `as_of`，
不内部取 `today()`（那会让结果依赖墙上时钟）。

**生产复验**：模拟一个没有 `paid_daily` 覆盖的交易日，5,550 行全部从快照
取到名称、**无名称 0 行**（修复前 96 行 / 1.73%）。

**衔接无缺口**：`paid_daily` 止于 2026-09-11（周五），首份快照 2026-09-14
（周一），中间两天是周末。

**本条了结。** 历史与增量两段都已闭合，换源前后 `daily_flags` 逐键一致。

## D-17 `688235.SH` 的总市值与总股本连续不自洽（已了结）

**登记日期**：2026-09-15。**状态：已于 2026-09-15 了结。**

增量规则 `A3.market_cap_vs_shares` 在 2026-09-15 的 5,548 个可比标的中只报
`688235.SH` 一只：收盘价 253.56 元、总股本 1,542,285,181 股，按恒等式应有
总市值 391,061,830,494.36 元；Tushare `daily_basic.total_mv` 实际给出
372,550,332,528 元，相差 4.73365%。后者反推总股本为 1,469,278,800 股。

这不是单日到货竞争：2026-09-10、09-11、09-14、09-15 四个连续交易日里，
`total_share` 都约为 15.423 亿股，而 `total_mv / close` 都稳定指向约
14.693 亿股。同期 QMT `share_capital` 最新记录同样约为 15.423 亿股。
流通市值与流通股本自洽，异常只在总股本/总市值这一组。

**最终归因**：规则口径错误，不是数据异常。既有换源报告已经确认 A+H 公司中
Tushare `total_share` 可包含境外股份，而 `total_mv` 的计价股本范围更窄；因此
“A 股收盘价 × 全球总股本 = 总市值”本来就不成立。百济神州的上交所公告进一步
确认它同时在上交所（688235）、港交所（06160）和纳斯达克（BGNE）上市。

公开依据：上交所《关于百济神州有限公司人民币普通股股票科创板上市交易的公告》
（https://www.sse.com.cn/disclosure/announcement/listing/ipo/c/c_20211213_5657032.shtml）
记录境内发行与上市股数；百济神州 2024 年半年度报告
（https://big5.sse.com.cn/site/cht/www.sse.com.cn/disclosure/listedinfo/announcement/c/new/2024-08-30/688235_20240830_4JV9.pdf）
列明上交所 688235、港交所 06160、纳斯达克 BGNE 三地证券。Tushare 官方
`daily_basic` 字段说明（https://tushare.pro/document/2?doc_id=32）确认
`total_share`、`float_share`、`total_mv`、`circ_mv` 是同一接口的独立输出字段，
没有声明四者可互相反算。

旧规则还有一个方向性错误：若旧源真的用 `market_cap / close` 反算
`total_shares`，它反而必然通过这个恒等式；正确直取全球总股本的 A+H 公司才会
失败，因此它无法实现“抓反算污染”的设计目的。

**结案处置**：不改写任何直取字段。规则改为三个始终成立的约束：

1. 全球总股本不少于 `total_mv / A股close` 所隐含的计价股本；
2. 计价股本不少于 A 股流通股本，流通股本不大于全球总股本；
3. `circ_mv / A股close` 匹配当日或上一交易日 `float_share`，相对容差
   0.01%。允许上一日是因为生产样本 `300803.SZ`、`603162.SH` 在股本变化日
   明确出现股本先切新值、市值仍逐位匹配上一交易日股本的日切口径。

## D-22 `joinquant_minute_bars` 与 `tushare_minute_bars` 从未进注册表

**登记日期**：2026-10-05。**状态：已修复，待生产验收。**

**事实更正（2026-10-05 生产只读复核）**：`joinquant_minute_bars` 真实落盘、被读、
被质检，却从未出现在 `DATASETS` 与 `schema` 里；生产实际有 233 个日分区。
`tushare_minute_bars` 是规范分钟构建器和质检代码中预留的覆盖路径，生产 warehouse
当前**没有该目录**，因为尚未购买 Tushare 分钟权限。原登记把“代码预留”写成“两张
表真实落盘”，结论不准确，本次按实际状态登记，不能再把预留契约误报成已有数据。

2026-10-05 的数据域目录（PR #110）把 47 张表全部归入业务域，并有测试断言「每张
物理表都被登记且只登记一次」——该断言通过。但它校验的是**注册表自身**的自洽，
不是「仓库里实际有的表都在注册表里」。所以「47 张一张没漏」**对注册表成立，对
仓库不成立**。

**后果两条**：

1. `joinquant.minute` 这条源解不出所属域——它在 `/data/catalog/sources` 的「所属
   域」为空，与 6 个 akshare 源并列。不是递归漏了，是没有任何已登记的表引用它。
2. `tushare` 是 `bar_minute_1m.source` 的合法取值，但没有对应的 `Source` 别名
   登记。`catalog-verify` 的别名解析规则因此可能把它判成 BAD——规则本身是对的，
   缺的是登记。

**不在 PR #110 里修的理由**（2026-10-05 裁决）：补登记会牵动 `schema` 注册与
`test_every_physical_dataset_is_registered_exactly_once`，是独立的契约改动，与
"加一条业务域轴"不是一回事。混在一起会让那个 PR 的评审面失焦。

**结案条件**：两张表进 `DATASETS` 与 `schema`，`tushare` 别名登记到对应 `Source`，
并补一条反向断言——**从仓库目录列出的物理表都必须能在 `DATASETS` 里找到**，
而不只是反过来。缺的正是这个方向。

**处置（2026-10-05）**：两张覆盖表共用与生产 Parquet 一致的物理契约并进入 Schema、
资产目录、行情域、字段血缘和规范分钟依赖图；`joinquant.minute` 与预留的
`tushare.minute` 均可递归解析，后者明确标记“未购买权限、无生产采集任务、无生产
分区”。资产盘点新增 warehouse 顶层目录反向分类，未注册目录写入
`coverage.unregistered_physical`，命令行生成报告后以非零状态失败；已知质量产物和
`.pre-*` 回滚快照单独列为辅助目录，避免把运维证据伪装成业务表。

## D-23 canonical 分钟线的「首根成交量为 0」分组治理

**登记日期**：2026-10-05。**状态：已完成分组治理，等待维护者验收。**

**事实**：2026-10-05 在节点实测 `bar_minute_1m` 全量（2020–2026，1636 个日分区，
26 GB），当日首根 bar 成交量为 0 的标的日共 **248,643** 个：

| source | 合计 | 前导零 bar 仅 1 根 | ≥2 根 |
|---|---:|---:|---:|
| `paid` | 238,702 | 202,789 | 35,913 |
| `qmt` | 9,940 | 9,475 | 465 |
| `joinquant` | 1 | 1 | 0 |
| **合计** | **248,643** | **212,265** | **36,378** |

分年（`paid`）：2020 = 31,701、2021 = 49,036、2022 = 57,262、2023 = 53,073、
2024 = 36,483、2025 = 11,126、2026 = 21。`qmt` 的 9,940 全在 2026。
`paid` 的 ≥2 根集中在 2022–2023（24,648，占 68%）。

**先更正一个错数**。2026-10-04 的 QMT 填充治理文档与 2026-10-05 的实施计划里都
写着「canonical 层 21,088 个标的日（qmt 9,940 + paid 11,147）」。那个数**只覆盖
了 2025–2026**：9,940 是 2026 的 qmt，11,147 恰好等于 2025 的 11,126 加 2026 的
21。2020–2024 的 227,555 个从未进入视野。错在把一次部分测量当成了全层结论，
与 10-04 「188 只全干净」那次是同一类错——**判据的覆盖面没有核对**。

**登记时的归因现状，分三群，只有一群确凿**：

1. **`qmt` 的 465 个（≥2 根）——确凿**。与 2026-10-04 在 `minute_bars` 修掉的
   缺陷同一个形状：区间查询把开盘前的无成交分钟用前收盘价填出来，一直填到首笔
   成交，所以是一长串而不是一根。465 这个数与当时独立测得的「465 个到达 09:31」
   吻合。
2. **`paid` 的 35,913 个（≥2 根）——不是上面那个缺陷，未归因**。余哈哈 ZIP 是
   另一条入库路径，不经 QMT 区间查询。形状相似不等于同因。2022–2023 的集中
   本身需要单独解释（候选：上游自身行为、盘中停牌、新上市首日），尚未查。
3. **212,265 个「仅 1 根」——很可能是真实的集合竞价无成交**。三个源、七个年份
   都落在标的日总量的 3–4%，这是流动性差的股票竞价无成交的正常比例。

**禁止动作**：不得把 248,643 整体当填充删除。按「禁任何反推与填充」，删行的前提
是**知道**那一行是伪造的，不是形状像。第 3 群若被误删，会把真实的「竞价无成交」
这一事实从数据里抹掉——那比留着填充更坏，因为它不可恢复且不可见。

**结案条件**：
1. 查清第 1 群在 canonical 层的去除方式（`minute_bars` 的修法不能直接套用，
   canonical 是另一套分区与合并逻辑），并按 10-04 的四步走：备份、只读报告核对、
   apply、复验；
2. 对第 2 群给出归因结论，再决定是缺陷还是事实；
3. 对第 3 群给出判定依据（最直接的是拿同期竞价 tick 或 Tushare 日线的竞价量交叉
   核对若干样本），确认是事实后，把「首根成交量为 0」这条质检判据改成只对多根
   前导零报警，避免每天 3–4% 的噪声掩盖真缺陷。

在 1–3 全部完成前，`bar_minute_1m` 不得作为回测的分钟数据源切换目标（这也是
月度研究单元至今没有加 canonical facade 切换的原因）。

**处置与最终结论（2026-10-06）**：本项采用「确定性分层抽样充分」作为事实判定
标准，而不是要求每个历史标的日都由第二家供应商逐行覆盖。理由是后者超出当前已购
数据权限：QMT 分钟历史只有滚动约一年；Tushare 历史分钟需要单独购买。抽样必须由
不同来源完成、固定选择方法、覆盖不同月份和交易所，并保留原始结果，不能只挑吻合
案例。

1. **QMT 多根 465 个——已修复。** PR #130 增加只读报告、逐分区原样备份、持锁
   apply、写后回读和全量复验。生产共修改 117 个日分区，删除 1,208 行；删除行的
   成交量和成交额均为 0。117 份备份共 2,386,826,236 bytes，备份 SHA256 全部等于
   修复前 SHA256，当前分区 SHA256 全部等于写后记录。修复后的 465 个标的日与当前
   QMT 构建结果逐键逐字段相等，独立日线质量规则 0 个违规。再次扫描全部 1,636 个
   canonical 日分区后，`qmt.multi` 从 465 降为 0。
2. **paid 多根 35,913 个——判为上游完整时间网格中的真实无成交分钟，保留。**
   全量 314,494 条前导行均为成交量 0、成交额 0、OHLC 平价；同一标的日的前导价格
   恒定，没有一条由 canonical 转换成真实成交。35,825 个案例的恒定价与独立日线
   `pre_close` 差异不超过 0.005 元；其余 88 个有除权或来源口径差异，但仍全部满足
   零量、零额、平价、恒定四项事实。对 QMT 滚动窗口内可回溯的全部案例按标的、按
   单日重新下载：63 个标的日、37 只证券，前导长度覆盖 2、3、4、5、7，
   QMT 的首笔真实成交时刻与 paid 的首个正成交量时刻 **63/63 完全一致**。因此它们
   与 QMT 区间查询伪填充形状相似、语义不同；不得删除。
3. **单根 212,265 个——判为 09:30 真实无成交，保留。** 从可回溯 paid 案例中用
   固定 hash seed 114，按「年份 × 月份 × 交易所」每层最多取 20 个，得到 201 个

   一致**。生产既有 QMT 归档与非 QMT 案例另有 22 个自然重叠，亦为 **22/22 一致**。
   三组独立证据均为零差异，满足本项原定的「交叉核对若干样本」结案条件。

质检据此收敛为 `B2.canonical_qmt_leading_padding`：只报告已有来源证据的 QMT 多根
前导填充；paid 多根与所有单根不再仅凭形状判错。这个选择不是忽略零量行，而是明确
